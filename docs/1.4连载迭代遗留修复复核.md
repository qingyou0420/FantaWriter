## 逐项证据

1. **thinking 只发主力档 — done**
   - `src/lib/ai.ts:345`：`const think = thinkingEnabled() && slot === "main";`，与修复清单建议逐字一致。`slot === "fine"` 时 `think=false`，请求体不带 `thinking` 且 `temperature` 保留（ai.ts:348、356–358）；`chapter_summary` 不在 `FINE_WRITING_MODES`，恒走主力档、照常思考。
   - 第 4 组组合测试已补：`src/lib/ai.test.ts:122–148`「thinking=1 + FINE_MODEL: chapter has no thinking and keeps temperature; summary still thinks」，断言 chapter 无 thinking 字段（含 JSON 序列化整体检查）、`temperature === 0.7`；chapter_summary 带 `thinking:{type:"enabled"}` 且 temperature 置空。原有三组 env 测试保留。

2. **工具页「本卷」不再写死第一卷 — done（下拉 + 默认双管齐下）**
   - 新工具函数 `volumeIdForLatestWrittenChapter`（`src/lib/volumes.ts:103–114`）：取已写正文中 order 最大一章所在卷；没有正文则退最后一章所在卷，再退第一卷。测试 `src/lib/volumes.test.ts:296–336`（两卷书只写了下卷一章 → 返回 v2）。
   - 工具页状态默认用它初始化（`src/components/ToolsPanel.tsx:84–86`），失效 id 时回落同源 fallback（:118–122），`runConsistency` 用解析后的 `resolvedVolumeId`（:128）。多于一卷时显示卷选择下拉（:605–618，带 aria-label）；单卷时无需选择、走默认，合理。

3. **timelineNote 可见可改，留空不写入 — done**
   - 增量确认面板新增「时间线（可改，留空不写入）」textarea，绑定 `deltaDraft.timelineNote`（`src/components/BeatWorkbench.tsx:301–313`）；面板说明补了「时间线」字样（:290）。
   - 「留空不写入」在消费端成立：`applyBeatDeltasToProject` 仅在 `deltas.timelineNote?.trim()` 非空时调用 `upsertTimelineLore`（`src/lib/beat-contract.ts:239–241`），作者清空输入框即可阻止写入世界观。

4. **续排 spinner — done**：`src/components/OutlinePanel.tsx:351` 与 `src/components/VolumesPanel.tsx:142` 均改为 `busy?.startsWith("outline_next")`，与 `busy = "outline_next:${volumeId}"` 匹配，「续排中…」可正常显示。

5. **导出文案 — done**：`src/components/ToolsPanel.tsx:487–489` 已写 `novels/书名/ch-001-标题.md`，并注明「同一章节再导出会覆盖，并清理该章因改序/改名留下的旧文件」，与第 6 项行为一致。

6. **导出清理同章旧文件 — done（桌面端全链路）**
   - 纯函数 `staleChapterRepoPaths`（`src/lib/export-chapters.ts:260–279`）：按 frontmatter `chapterId` 找同章异名旧文件，`projectId` 不符或非本次导出章节的文件一律不动（不会误删别的项目/别的章）。
   - 调用链：导出前经桥接 `listTextFiles` 列出目标目录（export-chapters.ts:447–456），`writeTextFiles` 带 `removeRelativePaths` 先写后删（:458–465），成功提示「已清理 N 个同章旧文件」（:482–484）。
   - Electron 端：新 IPC `fs:listTextFiles`（`electron/main.cjs:930–975`，只读 `.md`）；`fs:writeTextFiles` 删除循环（main.cjs:1011–1024）逐个走 `resolveRelativeUnderRoot`（:531–546，拒绝绝对路径 / `..` / 越出根目录），刚写入的文件绝不删，单个删除失败不阻断。`electron/preload.cjs:19`、`src/lib/desktop.ts:85–95` 类型齐备。
   - 测试：`src/lib/export-chapters.test.ts:243–279`——同章改序改名后旧文件 `ch-003-旧标题.md` 被判定应删，别章文件与本次新文件不受影响。

7. **config GET 失败不误清 FINE_* — done**
   - `configLoaded` 标志（`src/components/AppSettingsMenu.tsx:61`）只在 GET 返回 `res.ok` 并回填输入框后置 true（:124、:137）；保存时仅 `configLoaded || 输入框非空` 才带 `fineModel`/`fineBaseURL` 字段（:167–169），GET 失败后直接保存主力密钥不会把空串发过去删掉已有 FINE_*。`fineApiKey` 照旧 `|| undefined`。GET 成功后清空输入框主动删除的能力保留。
   - 追加提交 `47cdabe` 移除了 effect 内同步 `setConfigLoaded(false)`，避免 setState-in-effect 告警，语义不变。

- **微修：伏笔「其余」排序 — done**：`src/lib/memory-pack.ts:91` 由 `updatedAt` 改 `createdAt`（埋设新近度）；测试 `src/lib/memory-pack.test.ts:253–274`（旧埋但近期 updated 的排在新埋之后）。
