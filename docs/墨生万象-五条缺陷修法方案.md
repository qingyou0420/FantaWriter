## 〇、一段话结论

五条里 **三条是同一个「状态只看一个文件、写完不通知」的老病**（问心故事卡、织卷短题 / 提要、问心记录多余分组），一条是纯样式（落笔空态贴边），一条是打包配置（图标）。

- **D1 故事卡不同步**：`AskStoryRail` 只看 `story/story_card.md` 是否存在；该文件只在**建书那一刻**由 `persistAskArtifacts` 写一次，之后任何正典写入（包括截图里那次确认 `outline/volume_map.md`）都不会补它，前端也没有任何刷新信号。《醉词》这类 2.1.0 之前建的书（或走 REST/导入路径建的书）**永远**停在「故事卡还没落下」。修法：服务端新增派生型 `GET /books/:id/story-card`（有卡读卡，无卡从书名 + `author_intent.md` + `story_frame.md` 派生，并附 `askDone`），前端按 `askDone || card.source !== "none"` 切态；补齐正典写入后的 SSE / `bookDataVersion` 刷新链。
- **D2 短题 / 提要串栏**：AI 在问心 / 研墨对话里用 `write_truth_file` 写 `volume_map.md` 时，章条目是 `- 第1章：整段提要……` 这种**单行列表**；解析器 `EXACT_CHAPTER` 把冒号后的一切都当 `title`，`summary` 永远为空。织卷页直接把 `node.title` 灌进「短题」输入框，才出现 65 / 12。核心里已有 `splitOutlineTitleAndSummary` / `tidyVolumeMapMarkdown`，但只在**用户手动保存 / 点「整理卷纲」时**才触发，且分隔符集合漏掉 ASCII `,;:()`。修法：写入口（`commitOrStageTruthFile` + Studio PUT）统一归一化 volume_map；读侧 `outlineEditorSource` 按拆分结果回显；扩大分隔符；材料化器放弃 `.slice(0, 12)` 硬截。既有脏数据可用「整理卷纲」一键修复（无损、可撤销）。
- **D3 落笔空态贴边**：`LiteraryEmpty` 只有 `py-12`、没有 `px`，而 `BookDetail` 把它塞进 `rounded-xl overflow-hidden border` 的表格卡片里、紧接在 `<thead>` 之后。修法：空态时不渲染表头，给 `LiteraryEmpty` 加 `className` 透传，落笔页传 `px-6 py-14`。
- **D4 安装后图标仍旧**：`build/icon.ico` / `icon.png` 早在 #95 就换成了 Inkborne 圆标（已逐帧验证 7 个尺寸），**问题不在素材**，在 `electron-builder.yml` 的 `win.signAndEditExecutable: false`（2.0.0 起就有）。electron-builder 26 在这个开关为 false 时**整段跳过 rcedit**，`Inkborne.exe` 从未被写入图标资源，桌面 / 开始菜单快捷方式和固定到任务栏的图标都取自 exe → 一直是 Electron 默认图标（用户眼里的「旧图标」）。修法：删掉这一行（或设 true），`dist-win.mjs` 的兜底重试不能再静默退回 `signAndEditExecutable=false`；`main.cjs` Windows 下用 `icon.ico`。
- **D5 「新书与短篇」分组**：`Sidebar` 在每本书的会话之后固定渲染 `nav.projectTalks`（「新书与短篇」）= `bookId === null` 的全局会话桶（book-create / short / play / 通用 chat）；点它的标题还会 `nav.toChat()` 打开 `#/chat`，而 `ChatPage` 在 project-chat 模式下会**自动 `POST /sessions` 落一条空「chat」会话**，于是出现「新的会话 · 1 天」。修法：从「问心记录」删除该分组及其一整套状态 / 处理器；`#/chat` 不再自动落盘空会话。

建议拆 **两个 PR**：`P0-8 问心故事卡 / 织卷短题 / 问心记录`（D1 + D2 + D5，都是 studio + core 的状态与写入路径）；`P0-9 安装包图标 + 落笔空态`（D4 + D3，都是壳 / 样式，零逻辑风险，可先发）。均不 bump；发版时走 2.1.5。

## D1 问心侧栏故事卡状态不同步（图 01）

### 现象

左栏对话已完成「确认改正典 · outline/volume_map.md」并显示「已写入」；右栏 `AskStoryRail` 仍是「故事卡还没落下 / 重新推敲前提」。这本《醉词》已排 38 章、锁 7 卷，处于织卷阶段，右栏却说问心没落下。

### 根因（三层叠加）

**R1-a 状态源只有一个文件，且只在建书瞬间写一次。**

```91:107:packages/studio/src/components/AskStoryRail.tsx

        <AskStoryCard
          card={{ ...card, workingTitle: card.workingTitle || title }}
          editable={false}
          isZh={isZh}

      ) : (
        <LiteraryEmpty
          title={isZh ? "故事卡还没落下" : "No story card yet"}
          subtitle={isZh ? "从问心里重新推敲前提，把书名、一句话和梗概磨清。" : "Revisit the premise and settle the title, one-liner, and synopsis."}
          action={isZh ? "重新推敲前提" : "Revisit the premise"}
          onAction={reopen}
          testId="ask-empty"
        />
      )}
```

`fileData` 来自 `useApi("/books/:id/truth/story_card.md")`（L22）。而 `story/story_card.md` 的**唯一**写入者是 `lib/ask-artifacts.ts` 的 `persistAskArtifacts`，它只在两处被调用：

- `api/server.ts` L3317：REST `POST /books/create` 成功后；
- `api/server.ts` L5766：建书会话里 `create_book` 工具完成后。

两处都是**建书当下**。于是：
- 2.1.0（#95 引入故事卡）之前建的书、`fanfic/init` / `spinoff/init` / `imitation/init` / 导入路径建的书，磁盘上根本没有 `story_card.md`；
- 建书之后，无论问心 / 研墨怎么改正典（`author_intent.md`、`outline/story_frame.md`、`outline/volume_map.md`），都不会回写故事卡。

`write_truth_file` 白名单虽然允许 `story_card.md`（`core/src/interaction/project-tools.ts` L40、`truth-authority.ts` L17 归为 `direction`），但没有任何提示词要求模型在问心阶段去写它，实际不会发生。

**R1-b 正典写入后没有任何刷新信号。**

- 确认卡 `handleConfirmTruthDiff`（`ChatPage.tsx` L751–758）只 `postApi(/truth-proposals/:id/apply)`；`deriveInvalidationPaths`（`hooks/use-api.ts` L47–96）对这条路径返回 `[]`，不会触发任何 `useApi` 重取；也没有 `bumpBookDataVersion()`。
- 服务端 apply 路由（`server.ts` L4001–4032）与 `PUT /books/:id/truth/:file`（L6524–6558）**都不 `broadcast`**；SSE 里没有 `truth:*` 事件，`use-book-stage.ts` 的 `shouldInvalidateBookStageEvent` 只认 `write|weave|book:`。
- `AskStoryRail` 本身也不订阅 `bookDataVersion`（它只调 `bumpBookDataVersion`，不读）。

所以即便 R1-a 修好了，右栏也要刷新页面才会变。

**R1-c 「问心已落下」在系统里其实已有另一套判定，但右栏没用。**


`GET /books/:id/stage` 对《醉词》会返回 `steps.ask === "done"`（顶栏进程条的实心点也是这么亮的），但右栏用的是「文件存在」而非「阶段已成」。两套状态各说各话，就是用户看到的矛盾。

**顺带发现（同根）**：`pages/BookStudy.tsx` L146 读的是 `/books/:id/truth/story/story_card.md`——多了一层 `story/`，`resolveTruthFilePath` 白名单里没有这个键，永远 400 → 研墨页的 `oneLine` 永远为空。这条应在本轮一并修（改成 `/truth/story_card.md`，或直接改用下文的新端点）。

### 修法

**S1-1 服务端：新增派生型故事卡端点。**

`api/server.ts` 增加 `GET /api/v1/books/:id/story-card`，返回：

```ts
interface StoryCardResolved {
  readonly card: StoryCardDraft;            // workingTitle / oneLine / synopsis / genre? / tone?
  readonly source: "story_card" | "derived" | "none";
  readonly askDone: boolean;                // 直接取 resolveBookStage(...).steps.ask === "done"
}
```

派生规则放到 `lib/story-card.ts`（纯函数，可单测）：`deriveStoryCard({ title, authorIntent, storyFrameBody, genre })`
- `workingTitle` ← `book.title`；
- `oneLine` ← `author_intent.md` 去掉「暂定书名：」行后的第一段（≤ 80 字，超长用 `truncateOutlineLabel` 风格截断）；
- `synopsis` ← `author_intent.md` 剩余正文，或 `outline/story_frame.md` 去 frontmatter 后前 300 字；
- `genre` ← `book.genre`。
- 若 `story_card.md` 存在则 `source = "story_card"`，`parseStoryCard(content)` 后仍用 `book.title` 兜底 `workingTitle`（现有行为）。

**不在读路径写盘**。可选增强：`resolveBookStage` 已经在打开书时迁移 `workflow.json`，可以在同一处「askDone 且无 story_card.md」时把派生卡落成 `story_card.md`（幂等，presentation-only），但这属于数据修复，本轮不建议自动做，见「风险」。

**S1-2 前端：`AskStoryRail` 改用新端点，切态条件改为「问心已落下」。**

- `useApi<StoryCardResolved>("/books/:id/story-card")`；
- `ready = data.askDone || data.source !== "none"`；`ready` 时渲染 `AskStoryCard`（`source === "derived"` 时在 kicker 旁加一行小字「由正典推得 · 可编辑书名」，避免用户误以为 AI 写过卡）；否则才是 `LiteraryEmpty`；
- 「编辑书名」保存逻辑不变，但当 `source !== "story_card"` 时不要去 `PUT truth/story_card.md` 做正则替换（现 L49–60 会对 `null` 内容跳过，行为已正确，保留即可）。
- `BookStudy.tsx` L146 同步改成该端点取 `card.oneLine`。

**S1-3 刷新链：正典写入要通知到位。**

- `server.ts` apply 路由与 `PUT truth/:file` 成功后 `broadcast("truth:written", { bookId, fileName })`（命名与现有 `book:*` / `write:*` 对齐）；
- `use-book-stage.ts` `shouldInvalidateBookStageEvent` 加 `truth:`；
- `ChatPage.handleConfirmTruthDiff` 成功后 `bumpBookDataVersion()` 并 `invalidateApiPaths([/books/:id/story-card, /books/:id/truth/<fileName>])`；`deriveInvalidationPaths` 给 `truth-proposals/:id/apply` 增加对应返回（正则 `^/api/v1/books/([^/]+)/truth-proposals/[^/]+/apply$` → `["/api/v1/books/:id/story-card", "/api/v1/books/:id/stage"]`）；
- `AskStoryRail` 订阅 `bookDataVersion`，变化时 `refetch()`（与 `FoundationSection` L25–31 同款写法）。

### 验收标准

- 《醉词》这类无 `story_card.md` 的老书打开 `#/book/:id/ask`：右栏直接显示故事卡（书名 =《醉词》，一句话 / 梗概来自 `author_intent.md`），不再出现「故事卡还没落下」。
- 全新建书（问心 → 就此建书）右栏显示 `source = "story_card"` 的卡，行为与现在一致。
- 在问心里确认一次「改正典」（任意文件），**不刷新页面**：右栏 3 秒内更新；顶栏四步圆点同步（`/stage` 重取）。
- 真正尚未问心的空书（无 intent、无 frame、无章）仍显示空态 + 「重新推敲前提」。
- 研墨页顶部「一句话」不再恒空。
- 单测：`story-card.test.ts` 加 `deriveStoryCard` 用例（有 intent / 只有 frame / 全空）；`use-book-stage.test.ts` 加 `truth:written` 失效用例；`use-api.test.ts` 加 apply 路径的 invalidation 用例；`ask-page.test.ts` 增加「无 story_card 但 askDone → 渲染 `ask-story-card`」的 headless 用例。

### 风险 / 数据修复

- 派生卡只读不写，零数据风险；用户点「编辑书名」只改 `book.json` 的 title。
- 若后续想把派生卡落盘（自动生成 `story_card.md`），必须限制为「文件不存在 + askDone」且写入前再 `access` 一次防并发；本轮**不做**，避免在用户没确认的情况下往 `story/` 里多出一个文件被 `write_truth_file` 的 diff 门槛当作「已有内容」。
- `truth:written` 事件会让 `/stage` 多刷一次；`use-book-stage` 有 in-flight 去重，可接受。

## D2 织卷「短题 / 提要」串栏（图 02）

### 现象

第 1 章编辑区「短题」里是 65 字的整段提要（计数显示 `65 / 12`），「提要」为空；左树节点标题也是这段长文的截断。第 2、3 章同样。第 4–37 章是「（粗纲）」范围节点，尚未材料化。

### 根因

**R2-a 数据形态：AI 写进 `volume_map.md` 的章条目是单行列表，冒号后全是提要。**

图 01 的 diff 能直接看到写入格式：`- 第6-9章：四人日常成形段，吹笛舞剑……`。这类条目由问心 / 研墨对话里的 `write_truth_file` 提案写入，经 `commitOrStageTruthFile`（`core/src/interaction/truth-proposals.ts` L217–249）→ `applyTruthProposal`（L163–185）→ Studio apply 路由**原样落盘**，没有任何格式归一化。

**R2-b 解析器把冒号后的一切都当标题。**

```95:96:packages/core/src/utils/volume-map-tree.ts
const EXACT_CHAPTER = /^(?:#+\s*)?(?:[-*]\s+)?(?:\*\*)?(?:Chapter\s*(\d+)|第\s*(\d+)\s*章)(?!\s*[-~–—]\s*\d)(?:[:：-])?(?:\*\*)?\s*(.*)$/i;
const RANGE_CHAPTER = /^(?:#+\s*)?(?:[-*]\s+)?(?:\*\*)?(?:Chapter\s*(\d+)\s*[-~–—]\s*(\d+)|第\s*(\d+)\s*[-~–—]\s*(\d+)\s*章)(?:[:：-])?(?:\*\*)?\s*(.*)$/i;
```

`(.*)$` 整段进 `title`；`summary` 只从**下一行**收集（`collectSummary`，L261–276）。单行列表永远没有下一行，`summary === ""`。解析器保持无损是对的（编辑要靠 `lineStart/lineEnd` 精确回写），但**展示层**没有做任何补救。

**R2-c 织卷页直接回显 `node.title`，拆分只在保存 / 整理时发生。**

- `OutlineWorkspace.tsx` L145–151：`outlineEditorSource(selected)` → `setTitleDraft(source.title)`，原样灌入「短题」；
- L568–583：`<input maxLength={20}>` + 计数 `{[...titleDraft].length} / 12`——`maxLength` 不会截断已有值，硬上限 20 与提示 12 也不一致；
- 拆分逻辑 `splitOutlineTitleAndSummary`（core L1005–1024）只在 `saveSelected`（L261–286）和 `tidyOutline`（L303–316）调用。用户不点保存 / 整理，就永远是 65 / 12。

**R2-d 拆分规则本身有两个洞。**

```1010:1024:packages/core/src/utils/volume-map-tree.ts
  const trimmedTitle = title.trim();
  const trimmedSummary = summary.trim();
  if (trimmedTitle.length <= 20 || trimmedSummary) {
    return { title: trimmedTitle, summary, split: false };
  }
  const mark = trimmedTitle.search(/[，。；→]/);
  if (mark <= 0) {
    return { title: truncateOutlineLabel(trimmedTitle, 12), summary: trimmedTitle, split: true };
  }
  return {
    title: truncateOutlineLabel(trimmedTitle.slice(0, mark), 12),
    summary: trimmedTitle.slice(mark + 1).trim(),
    split: true,
  };
```

- 分隔符只认全角 `，。；→`；截图里的文本是 ASCII `,` `;` `(`——「辩堂正面交锋,苏缙以文脉……」会落到 `mark <= 0` 分支，短题变成粗暴的前 11 字 + `…`，提要 = 整段（含短题重复）。
- 阈值 `<= 20` 与提示词「短标题不超过 12 字」、UI 的 `/ 12` 不一致。

**R2-e 材料化器的兜底是硬截。**

```648:649:packages/core/src/agents/volume-map-materializer.ts
          title: (node.title || (params.language === "en" ? `Beat ${number}` : `第${number}章`)).trim().slice(0, 12),
          summary: node.summary || (node.title.length > 12 ? node.title : ""),
```

模型没按「标题一行、提要另起一行」输出时，短题 = 前 12 字硬切（可能切在词中间），提要 = 整段（含标题重复）。图 02 里第 4–13 章即将由它材料化，若不修，下一批也可能出现「短题是半句话」。

**R2-f 重复实现。** `studio/src/lib/copy-map.ts` L103–121 有一份一模一样的 `splitLongOutlineTitle`，只被自己的测试引用——应删除，统一用 core 导出。

### 修法

**S2-1 core：把拆分做成单一规则，并扩大分隔符。**

`utils/volume-map-tree.ts`：
- 新增常量 `MAX_CHAPTER_TITLE_CHARS = 12`（软上限，提示词 / 计数 / 拆分共用）、`HARD_CHAPTER_TITLE_CHARS = 20`（输入框硬上限）；
- `splitOutlineTitleAndSummary` 触发条件改为 `trimmedTitle.length > MAX_CHAPTER_TITLE_CHARS && !trimmedSummary`；
- 分隔符正则改为 `/[，,。．.；;：:→—–\-（(【\[]/`，取**第一个**命中位置；命中位置 `< 2` 视为无效再往后找下一个；找不到时回退到 `truncateOutlineLabel(title, 12)` 并把**完整原文**放进提要（现行为）；
- 短题去尾：去掉结尾的 `：:，,` 与成对未闭合的 `(（`。
- 新增 `normalizeVolumeMapChapterHeadings(markdown): string`：遍历 `parseVolumeMapTree` 的所有 chapter / range 节点，对 `split === true` 的节点用 `applyVolumeMapNodeEdit(markdown, node.id, { title, summary })` **就地改写**（从后往前应用，避免行号漂移）。与 `tidyVolumeMapMarkdown` 的区别：不重排、不改卷头、不动备注，**只碰超长标题那几行**，对其他行无损。

**S2-2 写入口统一归一化（防再混）。**

- 在问心里让 AI 写 `- 第2章：辩堂正面交锋,苏缙以文脉……`，确认卡里的 diff 已是「短题 / 提要」两行；ASCII 逗号 / 分号 / 括号都能作为分隔符。

### 风险

- 阈值从 20 降到 12 会让更多既有标题被判定为「需拆分」：只影响回显与下次写入，不主动改文件；13–20 字的纯标题（无标点）会被 `truncateOutlineLabel(…, 12)` 截断——因此规则里**必须**保留「找不到分隔符时提要 = 完整原文」，用户可自行复制回短题。

- 英文书：分隔符集合包含 `,.;:` 已覆盖；`Chapter N Title` 的短题按 12 **字符**算会偏紧，建议英文用 24（`language === "en"` 时阈值 ×2）。

2.1.1 起侧栏「对谈记录」改名「问心记录」，语义是**按书归组的问心会话**（CHANGELOG 2.1.1「对谈按书归组」）。短篇的问心入口在短篇书房（`ShortReader.openAsk` → `nav.toChat()`，会话 kind = `short`）；建书问心入口是侧栏「长篇」格（`handleOpenBookCreate` → `startFreshBookCreateSession`，且 `ChatPage` 会复用 `localStorage` 里未完成的 book-create 会话）。这两类会话都**有自己的入口**，不需要在「问心记录」里再列一次；而 `chat` 类通用聊天在墨生万象里已没有产品位置。用户判断「应删除」是对的。

### 修法

**S5-1 `Sidebar.tsx`：删除分组及其整套状态。**

- 删 L419–500 的分组按钮与 `Collapse`；
- 删 `projectChatExpanded` state 及所有 `setProjectChatExpanded`（L122、L173、L232、L240、L247、L423）；

- L170–176 的 `activePage === "chat"` effect 改为只 `setSessionsExpanded(true)`（或整段删除——`#/chat` 不再对应侧栏任何高亮项）；

**S5-2 `ChatPage.tsx` project-chat 模式：不再自动落盘空会话。**

L637–640 `createSession(null, "chat")` 改为 `createDraftSession(null, "chat")`（前端 draft，发第一条消息时才 `POST /sessions`，与书内问心一致，见 `store/chat/slices/message/action.ts` L276–301 的注释）。短篇入口 `ShortReader.openAsk` 已经用 draft，不受影响。`pickProjectChatSessionId`（`chat-page-state.ts` L160–173）仍可复用**有消息**的旧会话，不会丢历史。

**S5-3 既有脏数据。**

用户机器上已存在的空 `chat` 会话文件：
- 侧栏删组后**不可见**，不影响使用；
- 可选：`GET /api/v1/sessions?bookId=null` 列表侧过滤 `sessionKind === "chat" && messageCount === 0`（`SessionSummary` 已带 `messageCount`，`chat-page-state.ts` L20 / `store/chat/types.ts` L72），或在 `#/chat` 初始化时把这类空会话 `DELETE`。前者零风险，建议做；后者不做。
- 不做磁盘批量清理。

### 验收标准

- 侧栏「问心记录」展开后只列长篇书目（每书可展开会话 + 「+ 新开会话」），**没有**「新书与短篇」分组；`sidebar-sessions` 的 testid 与 `p1-ia.test.ts` L33 的顺序断言仍成立。
- 侧栏「短篇」格 → 进入 `#/chat` 短篇问心，能正常发消息、建短篇；短篇书房的「问心」按钮仍能回到该会话。
- 侧栏「长篇」格 → 建书问心，半途离开再回来仍复用同一会话（`isReusableBookCreateSession` 行为不变）。
- 直接访问 `#/chat`（无任何项目会话）：不再在 `books/…/sessions` 目录里多出文件；发第一条消息后才落盘。
- `rg "projectTalks|projectChatExpanded|SessionKindIcon" packages/studio/src` 为空；`pnpm test` 的 `p1-ia` / `ask-page` / `App.test` 通过。

### 风险

- 半途放弃的 book-create 会话（从未 `create_book`）失去侧栏入口：它们本来也只显示为「新的会话」，且「长篇」格会复用 `localStorage` 里最近一条；可接受。若产品后续要「未建成的书稿箱」，应做成独立入口而非混进问心记录。
- `#/chat` 路由本身保留（短篇 / 未来项目模式依赖），只是侧栏不再有它的入口。
