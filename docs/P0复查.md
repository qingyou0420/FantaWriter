# P0 复查记录

> 对象：分支 `cursor/p0-chapter-quality-1cae`（提交 `c8adf8c`，相对 `master`），对照已合入的 `docs/迭代方案.md`。
> 性质：只复查，不改功能。结论以逐函数、逐断言核对与本机实测（`npm test`、`npm run lint`、`npx tsc --noEmit`、`npm run build`）为准。

## 实测基线

- `npm test`：15 文件 95 用例全过（master 基线同样全绿，新增断言均在本分支）。
- `npm run lint`：22 errors / 20 warnings，与 master 完全同数——全部是存量债（electron 的 `require`、`set-state-in-effect` 等），本分支未新增。
- `npx tsc --noEmit`：**本分支新增 3 个类型错误，master 干净**（见「合入阻断」）。
- `npm run build`：**失败于 TypeScript 检查**。CI `test.yml` 只跑 vitest 所以会绿，但发版链路 `dist:win` 第一步就是 `npm run build`，合入即断发版。

## P0 逐项

### P0-1 篇幅硬约束 + 不足自动续 / 一键补足 —— 到位

- 数字区间：`LENGTH_RANGES`（`types.ts`），`LENGTH_LABELS` 由它派生；`lengthRangeFor` / `chapterBelowMin` / `chapterLengthRequirement`（新文件 `src/lib/length.ts`）。
- 注入提示词：`generalChapterUser` 正文要求第 5 条拼入 `chapterLengthRequirement`，含「硬性」「必须写满至少 min 字」「禁止…收束」。断言：`assemble.test.ts`「chapter prompt states a hard length band and forbids early wrap-up」（`3000–5000`/`硬性`/`禁止.*收束`），`length.test.ts` 五条，`types.test.ts` 锁死 3000/5000。
- 自动续：`generateChapter`（page.tsx 485–505 行）生成后 `chapterBelowMin` 则以 `mode:"continue"` + `continueLengthRequirement`（报差额字数）追一轮，最多一次；一键补足：`ChaptersReader.fillToLength`，`needsFill` 黄条 + 字数栏显示「目标 min–max」。全书队列走同一 `generateChapter`，自动覆盖。
- 小瑕疵（不构成「没到位」）：① 自动续的请求体传 `previousSummaries`（复数），而 `buildContinueUserPrompt` 只读 `previousSummary`（单数），自动续那一轮**没有前情摘要块**（状态卡/伏笔/lore 仍在，`existingText` 末 6000 字也在）；手动补足 `fillToLength` 传的是单数，正确。② `text = text + extra` 直接拼接，无分隔。③ DoD 里「10 章实测 ≥90% 达 3000 字」是人工验收项，仓内无任何实测记录。

### P0-2 本章只注入出场人物 —— 到位

- `OutlineChapter.castIds`（types.ts）+ `normalizeProject` 清洗；`CastPicker` 组件同时挂在 OutlinePanel 与 ChaptersReader 章卡。
- `formatCharacters(characters, { castIds })`（prompts.ts）：cast 全卡，其余走 `formatCharacterNameCard` 一行名片（姓名｜定位｜与 cast 相关的关系裁到 ≤48 字）；未选或 id 全失配时回退全量，不破坏旧项目。
- 状态卡去重：`buildCharacterStateCard`（memory-pack.ts）删掉全部静态人设字段，只剩「近期状态线索」+ 关注名单（有 cast 时只列 cast 名）。断言：`memory-pack.test.ts` 明确 `not.toContain("性格:")`、`not.toContain("乙的兄长")`；`assemble.test.ts`「selected cast gets full cards; others stay on one line」断言路人丁的外貌/背景不出现、名片单行。
- 边界：castIds 只在 chapter 模式生效，rewrite/continue/scene 仍全量注入——方案只要求 chapter，算符合。「3 章自评无乱入」无实测记录。

### P0-3 事实/文笔解耦 + 检索修正 —— 半到位

- 解耦到位：`ORIGINAL_SYSTEM_RULE` 追加「忠实的是情节、身份、事实……允许并鼓励重写原句」；`buildOriginalGrounding` 在摘录块前插「下列摘录只供核对情节与事实，文笔须按文风指南重写」。断言：`original.test.ts`「original system rule decouples facts from prose」。
- 检索词修正到位：`excerptKeysFromPayload` 重写为只取 canon 名/别名 + `characters[].name/aliases` + `loreEntries` 的 title/keys，整句切词删除。断言：「does not tokenize chapter summary sentences into excerpt keys」。
- 按章推进**只在 chapter 模式真正生效**：`selectOriginalExcerpts` 新增 `chapterOrder/chapterCount` 定位（focus = (order−0.5)/total），`windowsAround` 按距 focus 排序取窗。断言：「later chapters excerpt later original segments」。**但** `injectOriginalGrounding` 的 `chapterCount` 取自 `payload.outline.chapters.length`，而 `runRewrite` / `runContinue` / `fillToLength`（ChaptersReader）的请求体都**不带 outline** → total 默认 1，order≥2 时 ratio 钳到 1，focus 落在**原稿末尾**。给第 2 章做润色/续写时，摘录会锚到原文结尾——这几条路径的区段定位比改前（开头 1400 字 + 前 3 次命中）更偏。这是本项唯一没做穿的地方。
- 「实测文笔跟指南不跟原稿（人工判）」无记录。

### P0-4 fingerprints 注入 + 指南提权 —— 到位

- `GenerationSettings.learnedStyleFingerprints` 快照字段（types.ts + `createDefaultSettings` + `normalizeProject`），`applyLearnedStyle`（page.tsx）应用时一并存，清除时清空。

- 迁移注意：改动前已应用学习文风的老项目，settings 里没有指纹快照（normalize 补 `[]`），须在文风面板**重新应用一次**才吃到指纹。UI 无提示。

### P0-5 Volume.summary 进记忆包 + 章摘要可修复 —— 到位

- `formatVolumeMemory`（memory-pack.ts）：本卷主题 + 前序有摘要卷的一句话总结；`buildMemoryPack` 的 Pick 加 `volumes`，`priorBlock` 首块注入「## 分卷记忆」；`buildPreviousContext`（api.ts）Pick 同步。断言：`memory-pack.test.ts`「injects current volume theme and finished volume summaries」核对 `priorBlock` 同时含分卷记忆与章摘要。

## 声称的 P1 逐项

### P1-1 按卷生成大纲 —— 到位，但带一个回归风险

- 全链路齐：`outline_volume` mode（route.ts，maxTokens 8192）、`generalVolumeOutlineUser`（含前卷终局、期望章数、「不要规划其它卷」）、`previousVolumeEnding` / `mergeVolumeChapters`（volumes.ts）、`parseOutlineJson` 盖 `volumeId`、VolumesPanel「为本卷生成大纲」按钮。断言：`volumes.test.ts` mergeVolumeChapters 插位与重排、`assemble.test.ts` volume outline prompt。
- **回归风险**：`generateVolumeOutline`（page.tsx）合并时 `mergeVolumeChapters` 先剔除该卷原有章，新章是全新 id，随后 `chapters` 数组只保留能按 id 匹配上的正文行——**该卷已写的正文（含 versions）一键即失，且没有 confirm**。全书「生成大纲」在 master 上本来也是全覆盖，属对齐现状；但按卷按钮就放在卷条目上、一次点击只废一卷，对《醉词》这种已有旧稿逐卷推进的项目，误触成本高。建议合入前至少加一句 confirm（本次复查不改码）。

### P1-2 润色/续写带记忆 —— 半到位（功能在，带 bug）

- 做了的：`runRewrite` 传 `buildPreviousContext().priorBlock` + `sliceAroundSelection`（选区前后各 2000 字滑窗，替换原「fullContext 前 2500 字」截断）；`generalRewriteUser` 注入「前情记忆」块、滑窗全量、expand 目标字数（`expandTargetChars`，UI 1.5×/2× 下拉）；expand 的 maxTokens 提到 8192；continue 的「400–1200 字」改为 `continueLengthRequirement` 跟随篇幅档。断言：`assemble.test.ts`「rewrite user includes prior memory and the sliding window as-is」、`length.test.ts`「expand 2× is at least 1.6×」。
- **bug**：`ChaptersReader.tsx:100` `useState<1.5 | 2>("2")` 初值是字符串。后果一：tsc 报错（见下）。后果二：运行时默认态 `expandTargetChars(sel, "2")` 里 `Number.isFinite("2")` 为 false 回退 1.5×——UI 显示 2×、提示词写「约 2 倍」，实际目标字数按 1.5× 算，自相矛盾；用户动过一次下拉后才恢复正常。

### P1-3 detectCanonViolations 调用 —— 到位

- `generateChapter` 完成后前端调 `detectCanonViolations(text, fresh.canon)`，结果存 `ChapterContent.canonWarnings`（types.ts + normalize），章卡黄条「与锁定设定可能冲突：…」，不拦截不重生成，符合 DoD。检测本身仍只认「不是X」句式——方案本就只要求接线，不算欠账。
- 小瑕疵：手动编辑正文不清除/重算旧黄条，可能挂着过期警告；补足/续写路径不复检。均可接受。

### P1-4 去掉 user.replace 注入 —— 到位

- route.ts chapter 分支删除 `buildPriorContextBlock` + `user.replace(/## 正文要求/)`，`priorBlock` 经 `assemble` → `generalChapterUser(…, priorBlock)` 直接拼在「## 当前要写的章节」之前；`buildPriorContextBlock` 退化为只回传 priorBlock 的透传（现已无调用方，属死导出，可在 P2-1 一并清）。断言：「injects priorBlock once, before the current chapter heading」（唯一性 + 位置）与「route.ts no longer regex-injects prior before 正文要求」（直接扫 route.ts 源码）。
- 顺带确认无重复注入：chapter 请求体同时带 priorBlock 与散字段，但 general 分支只消费 priorBlock，`previousChapterSnippet` 在有 priorBlock 时被让位（priorBlock 内含结尾片段），无双份。

## 合入阻断（必须先修）

`npx tsc --noEmit` / `npm run build` 报 3 个新错，全部本分支引入：

1. `src/app/project/[id]/page.tsx:480` 与 `:488`：`chapterBody()` 的 `mode` 被 `...extra` 展开推宽成 `string`，不满足 `GenerateRequest.mode: GenerateTaskMode`。
2. `src/components/ChaptersReader.tsx:100`：`useState<1.5 | 2>("2")` 字符串初值（同时是上面 P1-2 的运行时 bug，初值改成 `2` 一并解决）。

CI 只跑 `npm test` 所以显绿，但 `dist:win`（发版）第一步 `npm run build` 必挂。

## 会让《醉词》仍写不好的残留点（按疼痛排序）

1. 润色/续写路径的原作摘录区段锚定错位（P0-3 gap）：改前几卷正文时摘录偏到原稿结尾。修法一行：这三处请求体补传 `outline`（或直接传 `chapterCount`）。
2. 「为本卷生成大纲」无确认地覆盖该卷已写正文（P1-1 风险）。
3. expand 默认档 1.5×/2× 不一致（P1-2 bug，与类型错误同源）。
4. 自动续写缺前情摘要块（`previousSummaries`/`previousSummary` 字段名错位）。
5. 老项目需重新应用学习文风才有指纹快照，无 UI 提示。
6. 人工验收类 DoD（10 章字数达标率、3 章无乱入自评、文笔 A/B）仓内均无记录，合入后要靠实际写《醉词》回补。

## 总评

五项 P0 与四项声称的 P1 都是真实现——提示词、数据链路、UI、测试断言四层齐备，不是改文案；但 **`npm run build` 类型检查挂掉会直接断 Windows 发版链路，现状不能合**；修掉那 3 个类型错误（其中 `expandScale` 初值顺手治好一个真 bug），再视情况补第 1、2 条残留，即可合。
