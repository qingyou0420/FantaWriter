## 阻断项 B1：卷节点就地编辑有损，失焦即写、静默丢正典行

`packages/studio/src/pages/OutlineWorkspace.tsx` 的 `saveSelected` 挂在标题输入框 `onBlur` 上、**无脏检查**，且总是同时传 `title` 与 `summary`。选中卷节点时 `summary` 取自 `extractOkr` 的解析结果；`applyVolumeMapNodeEdit`（`packages/studio/src/lib/volume-map-tree.ts` 第 357–376 行）的卷分支在 `summary !== undefined` 时把整个卷块重写为「卷头 + summary + 章节行区间」，导致两类行被静默删除：

1. 卷体内不匹配 `OKR_LINE` 正则（`Objective|Key Results?|KR\d|卷级目标|关键成果|关键结果`）的自由行——伏笔备注、非该格式的 OKR 子弹项等；
2. 章条目摘要在首个空行 / 280 字符截断点之后的续段（`collectSummary` 的 `lineEnd` 停在那里，卷重写时 `keptChapters` 只保留各章 `lineStart..lineEnd` 区间内的行）。

已实测复现（对该分支代码直接跑 `applyVolumeMapNodeEdit`）：

```text
输入卷体含：
  - 主角与执事结盟（不匹配 OKR 正则的备注行）
  备注：本卷埋药园钥匙伏笔，第 4 章收。
  （第 1 章摘要空行后的第二段）
选中卷 → 标题框失焦 → PUT 后三行全部消失。
```

`volume_map.md` 是 G2 protected 正典源、G1 的排纲真源。「就地编辑」蓝图允许人直写（§5.2 第 3 步），但前提是所见即所得；点一下卷标题再点别处就丢看不见的行，等价于无声正典损毁，且用户毫无感知（无 diff、无提示）。**必须修掉才能合**。修法建议（任选其一即可）：

- `saveSelected` 加脏检查（title/summary 与解析值相同则不 PUT）；
- 卷分支只替换实际解析为 OKR 的那些行（其余卷体行原样保留），或标题未变时走 title-only 分支；
- 补一条「卷编辑往返不丢未识别行」的测试进 `serial-cockpit.test.ts`。

顺带说明：章节点编辑分支**没有**此问题（只替换 `lineStart..lineEnd`，续段保留），G1 侧 `packages/core/src/utils/volume-map-entry.ts` 能识别编辑器写回的 `## 第 N 章 标题` 归一化格式，核对过。

## 逐项核查（hunt list）

### 1. 「驾驶舱只是皮肤，默认首页仍是文件+聊天堆」——**否**

- `packages/studio/src/hooks/use-hash-route.ts`：`#/book/:id` → `page: "book"`；`App.tsx` 该路由渲染 `SerialCockpit`，Chat 迁至 `#/book/:id/chat`。
- 全部入口都落驾驶舱：Dashboard 书卡（`pages/Dashboard.tsx` 第 230 行 `nav.toBook`）、侧栏书行（`components/Sidebar.tsx` 第 210 行）、建书完成事件（`hooks/use-session-events.ts` 第 59 行 `setRoute({ page: "book", bookId })`）。侧栏点**会话**才进 chat（第 229/239 行 `toBookChat`），语义正确。
- 驾驶舱内容是蓝图 §5.3 首屏五件套：下一章（号/题/卷位/一句话）、本卷 OKR+进度、到期/逾期钩子、上一章状态、单一落墨主按钮 + G1 结构化原因 + 去排纲/去审稿跳转（`pages/SerialCockpit.tsx`）。装配是纯函数（`lib/serial-cockpit.ts`），输入全部来自既有 P1 端点。

### 2. 「大纲有叠层面板 / 第二 AI 入口 / 选中节点无写或看动作」——**否**

- `pages/OutlineWorkspace.tsx`：两栏 grid（树+详情），无第三摞；进入时默认选中推荐节点（`recommendedOutlineNodeId(tree, nextChapter)`，对齐 §9-P2「默认选中推荐章」）。
- AI 入口只有织卷（预填指令跳 `#/book/:id/chat`）；无「优化大纲/重新生成/续排」类第二生成入口。nit：织卷按钮在页头、空态、详情面板出现三处，动作与去向相同，不算第二入口，但按 1.7 §4「生成入口收敛」精神可收成一处。
- 选中章 → 落墨·写这一章 / 查看正文；选中卷 → 动作回落到下一章的写/看（`selectedChapterNumber` 回落 `data.nextChapter`），无「选中即死路」。

### 3. 「写这一章越过顺序写作或绕 G1」——**否**

- `lib/serial-cockpit.ts` `resolveWriteThisChapterAction`：选中章 > 下一章 → `disabled` + `not_next_chapter`；= 下一章 → `enabled` 仍受 `preflight.ok`（G1）约束；已写 → `view`。有测试覆盖（`serial-cockpit.test.ts` 第 219–229 行「does not let a later selected node skip the next chapter」）。
- 实际触发只调既有 `POST /books/:id/write-next`（`startWriteNext`，master `server.ts` 3413 行），不存在按章定向的新管线入口；大纲页调用固定传 `skipPreviousApproval=false`。服务端仍是最终裁决者——即便前端状态陈旧也写不了错章（消灭了 1.7 §2.3 的写错章缺陷）。

### 4. 「G3 提案 / G5 critical / 锁与中止回归」——**无回归**

- 零后端改动：`packages/core`、`packages/studio/src/api`、`packages/desktop` 在 diff 中无一文件。驾驶舱消费的 `write-preflight`、`hooks/due`、`review-queue`、`truth-proposals(+apply/reject)`、truth GET/PUT 全部在 master `server.ts` 已存在。
- G3：`components/TruthProposalCard.tsx` 只调既有 apply/reject 端点；驾驶舱只计 `pending` 状态提案。G5：critical 快捷入口是加法（跳审稿章），approve 闸在 core 未动。锁：truth PUT 走 `acquireBookLock`（master `server.ts` 6082 行，`lock-and-truth.test.ts` 在跑）；`BookBusyCard` 仍挂在 `App.tsx`，中止链路无改动。
- 过卷不是 tab：`components/BookWorkspaceNav.tsx` 只有 驾驶舱/大纲/织卷/书稿 四页；过卷是驾驶舱里程碑卡（`cockpit-volume-close`）+ 卷详情提示条，符合 §5.5「低频仪式不常驻」。

### 5. 「1.x 启动路径」——**无**

无 Next.js / IndexedDB / `src/app/**` / `DiffConfirmGate` 任何回流；`package.json` 只改 test 脚本；启动路径仍是 `pnpm start` → Electron → InkOS Studio。

### 6. 测试

本地 `pnpm test` 全绿：core 7 文件 31 例、desktop 7 文件 31 例、studio 8 文件 73 例（含 `serial-cockpit.test.ts` 13 例、`use-hash-route.test.ts` 33 例）。
