# 墨生万象（Inkborne）· 问心去掉题材模版芯片方案

> 状态：**规划文档，本分支只含本文件，不改业务 / UI 源码，不 bump 版本。**
> 基线：`master` @ v2.1.6（`34d3ca7`，含 #117「问心去故事卡 / 研墨七段 / 书房四步文案」、#118「2.1.6」）。
> 用户需求：问心输入框上方那一行题材芯片（`Cozy Fantasy / English Cultivation / Dungeon Core / 恐怖 / Isekai / Portal Fantasy / LitRPG / 通用 / Progression Fantasy`）**直接删掉**，不要再出现在问心对话框上方。附图 `inkborne-bugs/05-ask-templates.png`。

---

## 〇、一段话结论

这行芯片只有**一个渲染点、一个数据源、一个挂载页**：`components/AskCreateRail.tsx` 里导出的 `AskGenreChips`，读 `GET /api/v1/genres`（即 `packages/core/genres/*.md` 题材档案，取前 8 个），只在 `pages/ChatPage.tsx` `mode === "book-create"` 分支挂载，也就是**只出现在「建书问心」（`#/book/new`）**。书内问心（`mode="book"`）、短篇 / 全局对话（`mode="project-chat"`）、互动影视（`interactive-film-authoring`）都不渲染它。

修法：**删 UI 渲染即可** —— 删 `AskGenreChips` 组件与 `ChatPage` 里的挂载块。**不动**数据源：`GET /genres`、`packages/core/genres/*.md`、侧栏「工具 → 题材模板」（`GenreManager.tsx`）是独立功能，建书 / 研墨 / 生成提示词都依赖题材档案，与这行芯片无关。无需「按模式隐藏」——芯片本来就只在建书问心渲染，删掉渲染点后所有问心都不会再出现。

## 二、改法：删 UI 渲染即可，不删数据

### 2.1 主修（必做，2 个文件）

**`packages/studio/src/pages/ChatPage.tsx`**

1. 删 L52 `import { AskGenreChips } from "../components/AskCreateRail";`
2. 删 L1110–1115 整块：

```tsx
{mode === "book-create" ? (
  <AskGenreChips
    isZh={isZh}
    onInsert={(text) => setInput(input ? `${input}\n${text}` : text)}
  />
) : null}
```

其余不动：`mode === "book"` 的 `reopen-ask` 块、`selectedSkills` 块、附件 input、输入框占位「告诉我你想写什么——题材、世界、主角、冲突」都保留（占位里提到「题材」是引导用户在对话里说，不是模版入口，符合「题材在对谈中定」的产品定位）。

**`packages/studio/src/components/AskCreateRail.tsx`**

1. 删 L143–167 `export function AskGenreChips(...)` 整个函数。
2. 删 L10 `import { useApi } from "../hooks/use-api";`（`AskCreateRail` 本体不用 `useApi`，删掉组件后此 import 就没有引用了；`tsconfig` 未开 `noUnusedLocals`，留着不报错但应清理）。
3. 文件头注释「Right rail on #/book/new: live story card + confirm dialog → create_book.」无需改。

### 2.2 不做的事（明确边界）

- **不删** `packages/core/genres/*.md`、`listAvailableGenres` / `readGenreProfile`、`GET/POST/PUT/DELETE /api/v1/genres*`、`GenreManager.tsx`、侧栏 `sidebar-tool-genres` 入口、`nav.genreTemplates` 文案。
- **不加**「按模式隐藏」的 prop / feature flag：芯片本来就只在 `book-create` 渲染，删渲染点即全站消失；再加开关是多余抽象。
- **不改** `lib/story-card.ts` 对 `genre` 的抽取（AI 回答里带题材时故事卡仍能填上 `genre`，建书 payload `createBook.genre` 照旧可选）。
- **不改** `README` / `docs/墨生万象-UI与四步流程重构方案.md` L181 / L515 的历史描述（那是已归档的方案文，不是现状文档）。

### 2.3 若将来想保留一个「题材模板」入口

用户已明确「直接删」，本方案默认全删。如后续需要，建议**不要**回到输入框上方一排芯片，而是：在建书问心右栏 `AskStoryCard editable` 的「题材」字段旁加一个 `select`（数据仍来自 `/genres`），这样入口归到故事卡字段，不占对话区。此为备选，不在本次范围。

## 三、测试改点

现有测试里**没有**任何对 `AskGenreChips` / `ask-genre-chips` 的断言（`src/__tests__`、`e2e/` 均检索为空），所以删掉后不会有测试红；需要**新增**反向契约，防止回流：

**`packages/studio/src/__tests__/p2-ask-ground.test.ts`** `describe("P2-1 问心")` 内追加一个 `it`：

```ts
it("does not render genre template chips above the ask composer", () => {
  const chat = read("src/pages/ChatPage.tsx");
  const rail = read("src/components/AskCreateRail.tsx");
  expect(chat).not.toMatch(/AskGenreChips/);
  expect(rail).not.toMatch(/AskGenreChips/);
  expect(chat + rail).not.toMatch(/ask-genre-chips/);
  expect(chat).toMatch(/reopen-ask/); // 书模式「重新推敲前提」芯片不受影响
});
```

原 `it("writes story_card.md and gates 就此建书 on three fields")` 里对 `rail` 的断言（`create-book-from-card`、`requestedIntent: "create_book"`）全部落在 `AskCreateRail` 主体与 `AskStoryCard`，删 `AskGenreChips` 不影响，无需改。

**回归命令**（在 `packages/studio`）：`pnpm typecheck && pnpm test`；`server.test.ts` L1136–1151 的 `/genres` 用例应继续通过（数据源没动）。

**e2e（可选）**：`e2e/` 现无建书问心用例；若要加，用 `page.goto("#/book/new")` 后断言 `getByTestId("book-create-ask")` 可见且 `getByTestId("ask-genre-chips")` 为 0 个。不强制。
