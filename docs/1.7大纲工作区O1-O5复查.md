## 〇、一段话结论

O1–O5 的主体是**真做了，且做得对路**：旧 `OutlinePanel` / `VolumesPanel` 确实从大纲页整体摘除（`page.tsx` 连 import 都删了），详情面板七个字段就地可编辑并走直写 + `markAuthorCanonEdit`，「写这一章」精确指向被点章且有单测，默认「第一幕/第一节」按「隐藏默认组而非隐藏层级」的正确口径处理，空态两按钮 + 进页选中推荐章也都在。PR 描述与代码相符，没有发现「说了没做」。**但合并前有两个必修缺陷**，都出在新详情面板与页面状态的接缝上：一是过卷向导一旦被打开（包括完卷时自动打开）就永远无法关闭，且新加的进页 effect 会在每次数据变更后把选中态强行拽回该卷，导致此后在大纲页**无法编辑任何章**；二是章详情的本地草稿只在换章时重建，「优化大纲」确认写入后面板仍显示旧文本，作者会以为润色没生效，此时再键入任何字符还会**用旧文本覆盖掉刚确认的润色结果**。这两条修掉之前不建议合并、更不要打包。

## 二、合并前必修（Blockers）

### B1 · 过卷向导一旦出现，大纲页从此无法编辑章

**症状**：`volumeWizardId` 被置位后（四个入口：卷详情「过卷向导」按钮、`DailyStatusBar` 的完卷跳转、章结算时 `volumeNeedsSummaryPrompt` 命中自动打开、批量任务收尾自动打开），在大纲页点开任何章、开始键入，约 200ms 后（防抖落库触发项目对象更新）右侧面板会被强行切回该卷的卷详情，章编辑中断。且全仓**没有任何** `setVolumeWizardId(null)`，`VolumeCloseWizard` 也没有关闭按钮——一旦触发，直到刷新页面前大纲页的章编辑都不可用。

**成因指认**：`page.tsx` 的进页 effect（`useEffect`，依赖 `[workspace, project, volumeWizardId]`）里 `if (volumeWizardId) { setSelectedVolumeId(volumeWizardId); return; }` 无条件执行。`project` 每次 `update()` 都换新引用，所以这个分支在大纲页会随**每一次落库**重跑。旧版里向导只是被动渲染在 `extra` 顶部（也没有关闭入口，属旧债），不劫持选中态；本 PR 的 effect 把旧债升级成了功能性阻断。注意：完卷自动打开是常规路径（写完一卷且卷摘要为空即触发），不是罕见操作。

**修复判据（done-when）**：向导打开时只在**打开那一刻**定位到卷节点一次，后续项目更新不再改写选中态；提供显式关闭（清空 `volumeWizardId`），关闭后可正常选章编辑；完卷自动打开的路径同样可关闭；手测「打开向导 → 点某章 → 连续键入 10 秒」面板不跳走。

### B2 · 「优化大纲」确认后详情面板不刷新，再编辑会覆盖润色结果

**症状**：在章详情点「优化大纲」→ `DiffConfirmGate` 确认写入后，面板各字段仍显示润色**前**的文本（作者会以为白花钱了）；此时在任一字段键入一个字符，防抖落库会把该字段的**旧文本+新字符**写回，覆盖掉刚确认的润色结果。

**成因指认**：`OutlineChapterDetail` 的 `const [draft, setDraft] = useState(chapter)` 只在挂载时取值，组件靠 `key={selected.id}` 换章重建；而 `proposalFromPolishedChapter`（`canon-gate.ts`）保持章 id 不变，确认写入后 key 不变、组件不重建、`draft` 不同步。所有输入框 value 都绑 `draft.*`，于是画面停留在旧值。同族问题：「写这一章」对话框 `onStart` 会把（可能被作者改过的）本章指导写回 `chapter.summary`，挂在后面的详情面板同样不感知。

**修复判据（done-when）**：确认润色（及任何外部对当前选中章的写入）后，详情面板立即显示新文本；面板有未 flush 的本地编辑时定义清楚合并策略（至少不得静默用旧值整段覆盖新值）；补一条单测或组件测试：「polish 确认 → 面板 summary 为润色后文本 → 键入一字 → 落库值为润色文本+一字」。

## 三、可接受遗留（不拦截合并，O6/P1/P2 处置）

1. **`OutlinePanel.tsx` / `VolumesPanel.tsx` 源文件仍在仓里**（无挂载点）。PR 已声明。建议 O6 落地、确认无回滚需要后删除文件，避免后人误挂回来。
2. **Studio 左侧壳 `ChapterNavList`（正文章节跳转条）在大纲页与树并存**。全局导航、职责不同，可接受；P1 可考虑在 outline 工作区折叠该条，进一步贴近「同屏唯一章列表」。
3. **卷范围批量补写入口消失**（原 `VolumesPanel` 的 `startBookJob("missing", volumeId)`）。全书「补写未完成章」基本覆盖；P1 在工具页批量任务区补一个卷选择即可。
4. **过卷向导渲染位置与选中卷解耦**：`OutlineWorkspace` 把 `volumeWizard` 塞给**当前选中卷**的详情，若选中卷 B 而向导属于卷 A，会把 A 的向导画进 B 的卡片。当前被 B1 的强制选中掩盖，修 B1 时需一并处理（`selectedVolume.id === volumeWizardId` 才渲染）。
5. **「AI 排纲 ▾」菜单无点外关闭**（对照 `AppSettingsMenu` 已有 mousedown 监听模式），点菜单项会收起、点空白不会。P2 体验补齐。
6. **删章遗留孤儿正文行**（见 O2 小偏差）。P2 数据卫生：删章时一并清理或在导出/体检工具里识别孤儿行。
7. **O6 整体后置**（过卷仪式完整归位、幕/节 CRUD、树上拖拽、批量标签抽屉）与 **H2**（提案只存 React 状态、刷新即丢）、**M-7**（中段插章账本错位）均维持原挂账，本 PR 未触碰也未恶化——但注意 O2 的「新增同级章」仍走全量重编 `order` 的老路径，M-7 语义原样存在。
8. **筛选+搜索叠加时卷标题命中被整枝隐藏**（见 O4 边角）。P2。
