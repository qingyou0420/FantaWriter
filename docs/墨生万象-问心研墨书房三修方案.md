# 墨生万象（Inkborne）· 问心 / 研墨 / 书房 三修方案

> 状态：**规划文档，本分支只含本文件，不改业务 / UI 源码，不 bump 版本，不改 appId / 安装包名。**
> 基线：`master` @ v2.1.5（`c981f18`，含 #113「P0-8 问心故事卡 / 织卷短题提要 / 问心记录收口」、#114「2.1.5」、#115）。
> 用户需求三条：① 问心页侧栏不再显示故事卡，故事卡归研墨；② 研墨页改为从上到下固定七段；③ 书房「四步一览」改成纯状态短句并修好对齐。本文逐条给出现状 / 根因（含代码路径）、文件级改法、数据映射、验收标准，最后给单 PR 的实现顺序与风险。

## 〇、一段话结论

三条本质上是**同一件事的三个面**：2.1.x 以来「故事卡（问心产出）」「设定（研墨产出）」「阶段状态（书房汇总）」三者边界不清 —— 故事卡挂在问心页右栏却是只读的正典视图；研墨页用「左目录 + 单面板」只露五个区，且 `story_frame.md` 的「世界规则」匹配串段（`主题与基调` 抢占了 `世界观底色`）；书房把「一句话故事」这种正文塞进四步一览导致栏位对不齐。修法：

- **A 问心去卡**：`BookAskPage` 只保留 `ChatPage`，删除 `AskStoryRail.tsx`（唯一消费者就是问心页；`AskStoryCard.tsx` 仍被建书页 `AskCreateRail` 复用，保留）。「编辑书名 / 重新推敲前提」的能力：前者迁到研墨「故事概要」段，后者 `ChatPage` 书模式输入框上方本来就有 `reopen-ask` 芯片，不丢功能。
- **B 研墨七段**：`BookGround.tsx` 从「`NAV` 五键 + 单面板」改成**纵向七段**（`基础设定 / 故事概要 / 世界规则 / 人物设定 / 关系与主线 / 结局与伏笔 / 其他待定项`），顶部一条粘性锚点条（七枚 `StageDot` + 段名，点击滚动），底部一条粘性操作栏（缺项摘要 + 「让 AI 铺细节」+ 「研墨定稿 / 重新定稿」）。数据源：段 1 = `book.json`（平台 / 题材 / 目标章数 / 每章字数）+ 故事卡 `tone`；段 2 = `GET /books/:id/story-card`（书名 / 一句话 / 梗概）+ `story_frame` 「主题与基调」段 + 折叠的 `author_intent.md`；段 3 / 5 / 6 = `story_frame.md` 三个区（修正 `ZONE_PATTERNS`，新增 `theme` 区）；段 4 = `roles/**`；段 6 另含 `pending_hooks.md`；段 7 = `open_questions.md`。服务端补两件小事：`PUT /books/:id` 放开 `platform` / `genre`；新增 `PUT /books/:id/story-card`（复用 `persistAskArtifacts` 落 `story_card.md`，替代 rail 里那段正则改 `working_title`）。定稿闸 `validateGroundConfirm` 逻辑不动，只把 `FRAME_SECTION_GROUPS` 第四组从「人物」放宽为「主题 / 基调 | 人物」并改提示文案，避免七段填齐了仍报「四段未齐」。
- **C 书房四步一览**：四行统一为 `StageDot | 步名（固定宽） | 状态短句` 三列栅格，全部 `items-center` + `whitespace-nowrap`。文案定死为：`问心 故事正典已完成 / 未完成`、`研墨 设定已定稿 / 设定未定稿 · N 位人物`、`织卷 已锁 N 卷 · 细纲已完成 / 未完成 · 章节规划 a/b`、`落笔 已写 x/y 章`。数据全部来自已有的 `useBookStage` + `snapshot.tree` + `book.targetChapters`，顺手删掉两次多余请求（`/story-card`、`open_questions.md`）。

建议**一个 PR、三个 commit**（C → A → B，风险从低到高），不 bump；发版走 2.1.6。

## A. 问心页侧栏不再显示故事卡

### A.1 现状

```40:52:packages/studio/src/pages/BookAskPage.tsx
  return (
    <div className="flex h-full min-h-0 flex-1">
      <ChatPage
        activeBookId={bookId}
        mode="book"

        theme={theme}
        t={t}
        sse={sse}
      />
      <AskStoryRail bookId={bookId} isZh={isZh} />

```

`AskStoryRail`（`w-80`，`lg:flex`）做三件事：① 渲染只读 `AskStoryCard`（书名 / 一句话 / 梗概 / 题材·基调）；② 「编辑书名」→ `PUT /books/:id` + 正则替换 `story_card.md` 里的 `working_title:`（L57–73）；③ 空态「故事卡还没落下 → 重新推敲前提」（`createDraftSession` + 预填 `REOPEN_ASK_PROMPT`）。

## B. 研墨页从上到下固定七段

### B.1 现状与根因

**B.1-a 结构**：左侧 `NAV` 五键（L44–50）+ 右侧单面板，`section` 状态决定渲染哪一块（L233–406）。一次只能看一段；没有「基础设定」「故事概要」；`终局` 与 `伏笔清单` 已在 P1-5 拆成两个 textarea 但仍挤在 `ending` 一个面板里。

**B.1-b 区匹配串段（真 bug）**：

```11:15:packages/studio/src/lib/story-frame-sections.ts
const ZONE_PATTERNS: Record<GroundFrameZone, RegExp> = {
  world: /世界|铁律|规则|world|tonal|rule|底色|主题/i,
  conflict: /冲突|主线|因果|对手|conflict/i,
  ending: /终局|结局|伏笔|endgame|ending/i,
};
```

架构师产出的 `story_frame.md` 固定四段（`core/src/agents/architect.ts` L244–262）：`## 主题与基调`、`## 核心冲突、对手定性、前台/后台双层故事`、`## 世界观底色（铁律 + 质感 + 本书专属规则）`、`## 终局方向 + 全书 Objective`。`extractStoryFrameZone(markdown, "world")` 用 `sections.find` 取**第一个**命中 —— `主题与基调` 命中 `主题`，于是研墨「世界规则」编辑器显示并回写的是**主题与基调**，真正的「世界观底色」段在 UI 里永远够不着。`replaceStoryFrameZone` 同样只替换第一个命中标题，所以「保存」不会撕文件，但用户以为改的是世界规则，实际改了主题段。

**B.1-c 定稿闸文案与结构脱节**：`validateGroundConfirm` 提示「故事框架四段未齐（世界 / 人物 / 冲突 / 终局）」，而 `storyFrameHasFourSections` 的判定是「≥4 个非空段 **或** 四组正则各命中一段」（`book-stage.ts` L44–49、L73–80），其中第二组是 `/人物|角色|character/` —— 架构师从不在 `story_frame` 写人物段（人物在 `roles/`），所以实际全靠「≥4 段」兜底。七段化之后若用户只填了世界 / 主线 / 结局三段（不填主题），会被这条闸拦住，且提示里的「人物」误导用户去 `story_frame` 里写人物。

**B.1-d 基础设定无处可改**：`platform / genre` 只在建书时写入，`PUT /books/:id` 不收；`BookSettingsDrawer` 只有每章字数 / 目标章数 / 状态。

**B.1-e 故事卡没有写入口**：`story_card.md` 唯一写者是建书时的 `persistAskArtifacts`；rail 的「编辑书名」是正则替换 frontmatter，遇到派生卡（`source === "derived"`，磁盘没文件）就只改了 `book.json`。

## E. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| B.5 修 `world` pattern 后，旧书里用户曾经在「世界规则」面板保存过的内容其实写进了「主题与基调」段 | 打开新研墨页时，那段内容出现在段 2「主题与基调」而不是段 3 | 数据没丢、位置更诚实；`Changelog` 说明一句。不做自动搬运（无法区分哪些是用户误写、哪些是架构师原文） |
| `FRAME_SECTION_GROUPS` 放宽 | 只可能让原本被拦的书通过，不会让已通过的被拦 | 单测覆盖「旧四段 / 新四段 / 三段」三种 |
| `PUT /books/:id` 放开 `genre` | 题材变化影响 `GenreManager` 题材档案加载与提示词 | 研墨段 1 编辑态给一行 muted 提示「改题材会影响后续生成的题材规则」；不改 `genreLock`（那是 `book_rules.md` / frontmatter 的事） |
| `PUT /story-card` 改书名 | `deriveBookIdFromTitle` 不会重算，`bookId` 不变 —— 这是期望行为 | 与现有 rail 行为一致 |
| 研墨页请求数从 6 涨到 8（多 `story-card`、`author_intent.md`） | 首屏多两个小请求 | 都是本地引擎，毫秒级；可接受 |
| 长页七段 + 每段独立保存 | 用户可能忘保存就切页 | 沿用现状（每段保存即落盘）；可选加 `beforeunload`/路由切换前的「有未保存改动」`ConfirmDialog`（不在本次范围） |
| 删除 `AskStoryRail.tsx` 影响 `p2-ask-ground.test.ts` 的 `read()` | 测试抛 ENOENT | A.3 已列出改点，与 commit 2 同时提交 |
| 回滚 | 三个 commit 彼此独立可 revert；commit 3 revert 会让「编辑书名」在 UI 上暂时消失（rail 已删），需连带 revert commit 2 | 顺序上 2 → 3 紧邻即可 |
