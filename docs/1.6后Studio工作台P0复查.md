## 二、合并前应补的洞（按严重度）

### H1 · packet 装配器是"陈列品"，实际写章没有用它

`canonical-packet.ts` 的 `buildCanonicalPacket`（作者意图 + 创作罗盘 + 滚动大纲窗 ±2 + 记忆包 + 本章指导）**只被助手栏"上下文"页签和测试引用**。真正的 draft 阶段（`page.tsx` 的 `generateChapter`）走的还是旧的 `buildPreviousContext`（即裸 `buildMemoryPack`）+ 契约 extras：

- **创作罗盘（`currentFocus`）从不进任何真实提示词**——这个 v3 新正典字段目前是纯装饰，作者在资料库里填的"必须保留/必须避免"对写章零作用；
- 助手栏上下文页签写着"与写章同一装配器"，与事实不符，方案 S5/S7 的 done-when（"packet dry-run 与实际写章一致（同一装配器）"）没有满足；
- 附带：`assistantSelection` 在 `page.tsx` 里是 `useState("")` 且从未 set，编辑器选区永远带不进助手栏，"已携带选区"分支是死代码，S7 的"正文页可带选区问落墨"没有满足。

### H2 · 提案确认闸有一条"丢产物"的缝

AI 提案的完整补丁（`CanonProposal.patch`）只存在 `pendingProposal` 这个 React 状态里；落到 `canonDrafts` 的记录只有 id/kind/summary，**不含补丁本体**。弹窗期间刷新或关闭项目：花钱生成的大纲/群像**永久丢失**，且 `canonDrafts` 里留下一条永远 pending、无任何界面可以重新打开/确认/放弃的死记录。方案 5.2 的语义是"产物先进 `runtime.drafts`，确认后才进 canon"——现在进 drafts 的只是登记条，不是产物。

### H3 · 结算重复计费 + 结果互相覆盖

`generateChapter` 内部保留了旧的异步 `chapter_summary` 调用（`summaryPromise`），而管线的 settle 阶段又调一次 `chapter_summary`。**每章两次主力档摘要调用**，方案 R5 明确要求"结算合并进现有摘要调用（同一次输出）"。更糟的是时序：批量路径里 `runBookJob` 在管线 settle 完成之后才 `awaitChapterSummary` 等第一次调用落地，第一次的结果会**覆盖** settle 写入的 `summary`/`pendingStateDeltas`，而账本里记的是 settle 那份增量——章面板显示的"待入账"与账本实际内容可能不一致。

### H4 · 审稿结果不回写 `reviewState`，"已审/待审"统计永久卡死

`runReviewForChapter` 只把审稿记录写进 `reviews[]`，从不动 `ChapterContent.reviewState`；写完的章固定是 `"draft"`。新流程里**没有任何路径能把一章标成"已审"**（旧定稿四件套已隐藏，`标为未审` 按钮只出现在已是 reviewed 的旧章上）。后果：审稿工作区与总览的"已审 n / 待处理 n"对新流程写的章永远显示待审，`nextHint` 会一直催去审稿。方案 7.6 明确"`reviewState` 按审稿结果置初值"。

### H5 · "按场景生成"是漏网的整章生成旧路径

正文页"大纲/场景"面板里的 **AI 规划场景 → 按场景生成** 在 `hideLegacyFlow` 下依然可达（`ChaptersReader.tsx` `generateByScenes`），一键覆盖整章正文：不建 run、不做 precheck、不持锁（与批量任务可并发）、不审稿、不结算、不写摘要。这正是 S8 要退役或收编的那类"绕闸整章生成"。（选区改写/续写/一键补足属于编辑器局部工具，有版本栈护着，可留。）

### H6 · 两处界面许诺了不存在的功能

1. 结算成功的提示写着"可在正文页**一键撤销本次写章**"——正文页没有这个按钮。commit 之后唯一的还原路径是残留锁弹窗（只对 status=running 的中断 run 出现）。方案 6.3.4 的"结算摘要 + 一键撤销"没有兑现，提示却先说了。
2. `DiffConfirmGate` 的"**编辑后写入**"按钮 `onEdit={() => applyPendingProposal()}`——与"确认写入"完全等价，没有任何编辑能力。方案 6.3.1 的三按钮语义（确认 / 放弃 / 编辑后写入）只实现了两个，第三个是假按钮。

## 三、中小问题与残余风险（不阻塞合并，但要记账）

- **M-1 批量绕过 precheck 阻断**：`runWritePipeline` 对 `fromJob` 调用完全忽略 precheck 结果（含无 API Key、存储不可写）。有 bookJob 互斥兜底，失败会在逐章报错，但"批量每章仍走写前检查"这句 PR 描述只对了一半。
- **M-2 单人人物 AI 扩写不过闸**：`CharactersPanel` 的"AI 扩写/优化"结果进编辑器草稿，作者点保存后走 `onChange → markAuthorCanonEdit` 直写——AI 产物被记成"作者修改"，没有 before/after diff。方案 6.2 把 `expand/optimize character` 列为织卷提案类任务。编辑器保存算一种弱确认，暂可接受，但痕迹语义是错的。
- **M-3 `proposalFromLore/Threads/Premise/Focus` 是死代码**：世界观/伏笔/意图/罗盘目前没有 AI 写入路径所以没接闸，函数写了没人调。不算洞，但说明这四类一旦将来加 AI 入口，很容易忘了接。
- **M-4 重跑结算不幂等**：`mergeCharacterStates` 对同一 chapterOrder 直接追加行，不去重。"重跑结算"按一次账本就多一份近似重复的状态行（被 KEEP=6 封顶，但会挤掉真历史）。
- **M-5 助手栏每次键入都重算 packet**：`AssistantRail` 的 `useMemo(() => previewCanonicalPacket(...), [project, chapterId])` 在正文区每个键入（project 每次变更）都跑一遍 `buildMemoryPack`，且**收起状态下也在算**。百章级长书上是 R1 类首感风险。
- **M-6 `FocusPanel` 用旧快照整体替换项目**：`onChange={(next) => update(() => next)}`，`next` 由组件 prop（可能过期的 project）构造。若异步写入（如摘要落地）恰好插在中间会被键入覆盖。其它面板都是 `update((p) => ...)` 的函数式补丁，唯独这里例外。
- **M-7 中途"新增同级章"重排后续全部章序**：`addBlankOutlineChapter` 插入后 `order` 全量重编。账本行、`accountRepairMarks` 都按 chapterOrder 记，已写书中段插章会让这些记录指向错章。S4 的 done-when 只保护了"续排追加"场景。
- **M-8 "定位原文"只开章不定位**：`ReviewWorkspace` 算好了 `locateEvidenceOffset`，`page.tsx` 的 `onLocate` 把 offset 扔掉，只切到正文工作区。
- **M-9 迁移备份无应用内恢复口**：`migration-backup-schema-v3` 只写不读，出事只能开 devtools 手捞（与历史 `migration-backup-v2/v3` 同款取舍）。
- **M-10 "整章事务"实为"快照可回滚"**：管线各阶段是多次 `update` + 防抖落盘，不是方案 7.7 字面上的"一次 `upsertProject` 提交单元"。中间态会落盘，但快照存于 run 记录且同样落盘，崩溃恢复经残留锁弹窗成立——语义达意，措辞与方案有出入，记录在案即可。
- **M-11 `hasApiKey` 未知时不阻断**：`/api/config` 延后加载或失败时 precheck 拿到 `undefined`，"开始写"可点，失败推迟到 draft 阶段报错。小事。

## 五、给后续编码 Agent 的补丁清单（症状 + 完成判据）

按优先级排列，均为接线层改动，不动 schema、不动壳。

1. **管线吃真 packet**
   症状：`currentFocus` 与滚动大纲窗不进写章提示词；助手栏 dry-run 与实际发送内容不一致。
   完成判据：`generateChapter`（管线 draft 阶段）的 priorBlock 来自 `buildCanonicalPacket`；助手栏预览与实际请求体中该块逐字一致（可加一条对拍单测）；`currentFocus.mustAvoid` 里写的一句话能在 dry-run 与实际 payload 中同时看到。
2. **提案产物落库 + 待确认列表**
   症状：确认弹窗期间刷新，AI 产物丢失，`canonDrafts` 留永久 pending 死条目。
   完成判据：`CanonDraft` 携带 proposal 的 `changes` 与 `patch`（或可重建的等价物）；资料库或总览有"待确认提案 n"入口可重新打开闸；刷新后重开项目仍能确认或放弃；拒绝/确认后条目状态正确。
3. **结算只调一次摘要**
   症状：每章两次 `chapter_summary`；批量路径下第一次的结果晚到覆盖 settle 产物。
   完成判据：管线路径（含批量）全章只发一次 `chapter_summary`；`awaitChapterSummary` 等的就是 settle 那次；章的 `summary`/`pendingStateDeltas` 与账本入账来自同一次调用。
4. **审稿回写 `reviewState`**
   症状：新流程写的章永远"待审"，总览/审稿统计卡死。
   完成判据：`runReviewForChapter` 成功后按既定规则置 `reviewState`（建议：无 high 问题置 reviewed，有 high 保持 draft 并计入"阻断"）；总览 `pendingReviewCount` 在审完后下降；跳过审稿的章有明确显示口径。
5. **收编或封死"按场景生成"**
   症状：正文页场景面板可绕过管线覆盖整章。
   完成判据：要么该按钮走 `runWritePipeline`（scene 模式作为 draft 阶段的实现），要么在 `hideLegacyFlow` 下隐藏、并把场景规划保留为只写 `scenes` 元数据的工具；全仓不再存在不建 run 的整章生成入口。
6. **兑现或收回两个假承诺**
   完成判据：正文页对最近一次 committed run 提供"撤销本次写章"（用 run 快照还原，含账本/伏笔），或删掉提示文案；`DiffConfirmGate` 的"编辑后写入"提供至少字段级文本编辑后再落库，或先移除该按钮。
7. **小修打包**（可合一个 PR）：批量路径尊重 precheck 的 block 项（至少 API Key 与存储）；`FocusPanel` 改函数式更新；`mergeCharacterStates` 对同 chapterOrder 同名去重或替换；`AssistantRail` 收起时不算 packet、展开时防抖；`onLocate` 消费 offset 滚动定位；单人人物 AI 扩写保存时改走提案闸或至少不打 `markAuthorCanonEdit` 痕迹。
