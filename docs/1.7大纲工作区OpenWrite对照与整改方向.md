## 〇、一段话结论

作者的原话是「**特别混乱，不知道怎么用**」。读完代码后的判断：这不是功能缺失，而是**信息架构失败**——1.6 迭代的 S4 切片只做了「新树 UI」这一半，把旧 `OutlinePanel` 和 `VolumesPanel` 原样挂在新树详情页的下方当「备用入口」（P0 复查里也如实记了这一点），结果同一页上有**两份章节列表、两个互不同步的选中态、三十多个按钮、两套写入心智模型（手工直写 vs AI 草稿闸）**，而新树自己的详情面板却**连摘要都不能编辑**、「用此章创建正文」和「原文定位」是两个字面不同但行为完全相同的按钮。作者感到混乱是对的。整改方向不是加功能，而是**做减法**：像 OpenWrite 那样，大纲页只留「一棵树 + 一个就地可编辑的详情面板 + 一个收敛的 AI 排纲入口」，其余全部移走或折叠。

## 一、OpenWrite 的大纲工作台实际是怎么工作的

以下描述来自其 README、`models/outline.py`、`tools/studio_assets/js/application.js`（`loadOutline` / `renderOutline*` / `openOutlineEditDialog` / `openSmartWriteDialog` 等函数）与截图，不是想象。

### 1.1 单一真源（SSOT）

- `src/outline.md` 是**唯一大纲真源**。规划过程中的 `outline_draft.md` 只是草稿候选，README 的 FAQ 专门强调「它不是另一份大纲」。
- Studio 里对树的每一次改动（改名、新增、删除、改摘要）都通过 `/api/outline/edit` **增量写回 `src/outline.md`**，并自动建立 Git 存档；请求携带 `revision`，防止覆盖外部编辑器刚写入的内容。
- 数据模型是四级节点（`models/outline.py`：master/arc/section/chapter，UI 标签为 卷/幕/节/章），章是最小写作单元，节/幕承载中/大弧线（目的、戏剧结构、情感走向）。**层级是真实可编辑的资产，不是装饰**。

### 1.2 一棵树 + 一个详情面板，编辑就地发生

大纲工作区只有两栏，没有第三块：

- **左树**：
  - 顶部统计行「n 卷 n 幕 n 节 n 章 n 已写」；
  - 「+新增卷」「编辑原文」（直接打开 `src/outline.md`）、刷新、「写推荐章节」四个顶部动作；
  - 搜索 + 全部/待写/已写 三态筛选。筛选按**整枝**判定（`outlineNodeVisible`：自己或任一后代命中才显示），并显示「命中数/总数」，不会留下一排空组头；
  - 每个节点可展开/收起（含全部展开/收起）、行内改名、行尾悬浮「在此节点下新增下级」按钮（按钮文案随层级变化：新增幕/新增节/新增章）；
  - 已写章节打勾，待写显示空圈。
- **右详情**（选中任一节点）：
  - 面包屑路径（卷→幕→节→章，可点击跳到上级）；
  - **标题就地可编辑**（contenteditable，回车/失焦提交）；
  - 元信息徽标：层级、节点 id、在 `outline.md` 中的行号、状态（待写/已写）、「大纲 x / y 字」（当前摘要字数 / 该层级的大纲字数目标）、「正文目标 n 字」；
  - **摘要就地可编辑**（内嵌 Markdown 编辑器 + 保存按钮，即截图里的富文本小工具条）；
  - 动作按钮一组：「新增下级 X」「新增同级 X」「删除」（不能安全删除时禁用并给出原因 `delete_blocked_reason`）「原文定位」（跳到 `outline.md` 对应行）「**用此章创建正文**」。

### 1.3 从章节点到「开写」是一次点击

- 「用此章创建正文」直接打开**写章对话框**（`openSmartWriteDialog(nodeId)`）：预填本章大纲、本章指导、字数目标，确认后进写作管线。
- 树顶的「写推荐章节」用服务端算好的 `outline.recommendation`（下一个该写的章 + 目标字数）；进入大纲页时**默认选中推荐章**，作者打开页面就知道「现在该写哪一章」。
- 模型未配置或没有推荐章时按钮禁用——不可用的动作不摆出来骗点击。

### 1.4 作者从零到「本章可写」的真实路径

1. 建书后引导先补齐资产（意图/人物/背景），大纲为空时引导给「生成大纲」动作；
2. 与 Goethe 在 AI 协作里讨论，Goethe 给出大纲草稿，**展示 diff，本轮确认后写入 `src/outline.md`**；
3. 到大纲工作区看树，行内改名、就地改摘要、按需增删节点；
4. 选中一章 →「用此章创建正文」→ 填本章指导 → Dante 走 写前检查→组装上下文→初稿→结算；
5. 之后每天打开：树默认停在推荐章，点「写推荐章节」继续。

要点：**手工编辑与 AI 生成写的是同一份真源；页面上任何时刻只有一份大纲视图**。混乱无从产生。

## 二、幻想作家 1.7.0 的大纲页实际是怎么工作的

### 2.1 数据层（这部分其实是健康的）

- 章数据在 `project.outline.chapters`（扁平数组，全书连续 `order`），卷在 `project.volumes`；
- `project.outlineTree` 是**分组视图**（卷→幕→节→章，只存 chapterId 引用），由 `src/lib/outline-tree.ts` 的 `syncOutlineTree` 在每次章集合变化后同步：删章去引用、新章追加到该卷末节、缺卷补上；
- 每卷迁移/新建时自动包一层**默认「第一幕/第一节」**（`createDefaultAct`），`applySchemaV3`（`src/lib/studio-v3.ts`）保证每个项目打开后都有这棵树；
- 手工插章走 `src/lib/outline-edit.ts` 的 `addBlankOutlineChapter`（直写 + `markAuthorCanonEdit` 记痕迹）；AI 排纲（`outline` / `outline_volume` / `outline_next`）走 `canonDrafts` + `DiffConfirmGate` 确认闸，确认后 `applyPendingProposal` 同步树。

即：**单一真源在数据层是成立的**（章只有一份，树只是视图）。混乱几乎全部发生在界面装配层。

### 2.2 界面层：一页三摞东西

`page.tsx` 的 `workspace === "outline"` 分支渲染 `OutlineWorkspace`，并通过 `extra` prop 把三个组件塞在详情面板**下方**（作者需要滚动才能发现，且发现后更晕）：

```text
大纲工作区（一屏内自上而下）
├─ OutlineWorkspace（1.6 新建）
│   ├─ 左树：统计行、搜索、全部/待写/已写、卷→幕→节→章缩进列表
│   └─ 右详情：章标题 + 待写/已写徽标 + 只读摘要
│       └─ 按钮：新增同级章 / 用此章创建正文 / 原文定位
└─ extra（滚动可见）
    ├─ VolumeCloseWizard（过卷向导，条件出现）
    ├─ VolumesPanel（旧分卷面板，整个原样挂入）
    │   └─ 每卷一行 8 个按钮：上移/下移/为本卷生成大纲/续排本卷 n 章/
    │      过卷向导/AI 生成本卷摘要/生成本卷/删除 + 卷摘要/弧线目标/出卷局面 3 个文本框
    └─ OutlinePanel（旧大纲面板，整个原样挂入）
        ├─ 「大纲总览」卡：重新生成大纲 / + 添加章节 / 续排本卷 n 章 / 结局方向勾选
        ├─ 「批量标签」卡：全选/清空/标签选择器/清空所选章标签
        └─ 双栏「章节目录 + 章编辑器」：第二份章节列表（拖拽排序、复选框），
           每章编辑器含 剧情摘要/关键情节点/章末钩子/节奏备注/标签/出场人物 6 个字段
           + ↑ ↓ / 优化大纲 / 生成本章 / 在本章后插入 / 删除 7 个按钮
```

### 2.3 关键交互的真实行为（逐个按钮核对过）

| 界面元素 | 位置 | 实际行为 |
|---|---|---|
| 「新增第一章」 | 新树详情区空态 | `addBlankOutlineChapter`：直写一条空章 + 空正文行，选中它。**但详情面板不能编辑摘要**，作者下一步不知道去哪填内容 |
| 「新增同级章」 | 新树详情 | 在选中章后插入空章，随后 `order` 全量重编（P0 复查 M-7：已写书中段插章会让按章序记的账本/修痕错位） |
| 「用此章创建正文」 | 新树详情 | `setSelectedChapterId + goWorkspace("manuscript")`——**只是跳到正文页，什么都不创建、不写** |
| 「原文定位」 | 新树详情 | 与上一条**逐字相同**的处理函数。两个按钮、一种行为 |
| 「AI 生成大纲 / 重新生成大纲」 | 旧 OutlinePanel | `generateOutline` → 草稿入 `canonDrafts` → 弹 `DiffConfirmGate` 确认后落库并同步树 |
| 「为本卷生成大纲」 | 旧 VolumesPanel 每卷 | `outline_volume`，同上走闸；会**替换**本卷已有章（有 confirm 提示） |
| 「续排本卷 n 章」 | **两处**：旧 OutlinePanel 顶部 + 旧 VolumesPanel 每卷 | `outline_next` 滚动排章，走闸追加 |
| 「生成本卷」 | 旧 VolumesPanel 每卷 | 这不是排大纲，是**批量生成正文**（`startBookJob`），和左右邻居的「生成大纲」字面几乎无法区分 |
| 「生成本章」 | 旧 OutlinePanel 章编辑器 | `setSelectedChapterId(ch.id); requestWriteNext()`——`requestWriteNext` 读的是**本次渲染的旧选中值**（闭包内 `effectiveSelectedId`，`setState` 未生效），且 `findWriteNextChapter` 的语义是「当前章**之后**第一个未写章」，所以点第 3 章的「生成本章」很可能弹出**第 4 章**的写前对话框 |
| 「写下一章」 | 顶栏（全局） | `findWriteNextChapter` → `WriteNextDialog`（写前检查 + 本章指导）→ `runWritePipeline`。没大纲时报错「没有可写的下一章，请先排大纲」并**跳回这个大纲页** |

### 2.4 新树本身的缺口

- **详情只读**：`OutlineWorkspace` 的右栏只显示 `selected.summary`（「（无大纲摘要）」），没有任何输入框。要改摘要/标题/钩子，必须滚到楼下旧 `OutlinePanel`，在**另一份列表**里再找一次同一章（两边选中态不互通：新树用页面级 `selectedChapterId`，旧面板用自己的 `activeId`）。
- **删除、改名缺失**：新树详情没有删除章、重命名章；只能去旧面板。
- **假层级**：树永远显示「第一幕/第一节」两级组头，但全仓**没有任何 UI 能新增/改名/移动幕和节**（`outline-tree.ts` 只有 `createDefaultAct` 默认组）。统计行「1 卷 · 1 幕 · 1 节 · 8 章」如实地模仿了 OpenWrite 的样子，却没有它的实质，只给作者添了两级要理解的名词。
- **筛选留空壳**：待写/已写筛选与搜索只过滤**章行**，卷/幕/节组头照常渲染；空书或筛空后是一列光秃秃的「第一卷/第一幕/第一节」。
- **字数目标缺席**：详情写「大纲 n 字 · 目标见生成参数」——把作者支到工具页去查一个本该就地显示的数字（OpenWrite 显示「大纲 62 / 220 字 · 正文目标 6,000 字」）。

### 2.5 对照 1.6 方案的说法

方案 S4 的原话是「`outline_next` 等生成入口**迁入**（树工作区），产物先进 drafts 再经闸确认」，第八节承诺「S8 拆除旧入口」。实际发货：闸做了（真），但生成入口没有「迁入」，而是把两个旧面板**整体挂进**大纲区；S8 拆的是三段式顶部导航，没拆大纲区里的旧面板。P0 复查对 S4 的判词「旧 `VolumesPanel`/`OutlinePanel` 挂在大纲区作备用入口……达标」把这个状态合法化了——从功能清单角度确实都在，但从作者视角，这正是混乱的最大来源。

## 三、为什么「特别混乱」——逐条映射到文件与入口

按作者实际会遇到的顺序排列，每条都能在代码里指认。

1. **同一页两份章节列表、两个选中态。**
   `OutlineWorkspace` 左树（`selectedChapterId`，页面级）与 `OutlinePanel` 的「章节目录」（组件内 `activeId`）互不同步。在上面选了第 4 章，滚下去看到的编辑器却停在另一章。作者无法建立「我现在操作的是哪一章」的稳定感知。
2. **看的地方不能改，能改的地方要再找一遍。**
   新树详情面板只读（`OutlineWorkspace.tsx` 右栏无任何 input/textarea）；编辑六个字段全在楼下旧面板。这是「不知道怎么用」最直接的成因：作者第一眼看到的界面不支持他想做的第一件事（把这一章要写什么记下来）。
3. **两个按钮一种行为，且名不副实。**
   「用此章创建正文」与「原文定位」在 `page.tsx` 里是两段逐字相同的处理（选中 + 跳正文页）。前者不「创建」任何东西，后者定位的也不是「原文」中该章大纲对应的位置。OpenWrite 里这两个是真正不同的动作（开写章对话框 / 跳 `outline.md` 行号）。
4. **卷/幕/节三级组头是不可操作的装饰。**
   永远存在的「第一幕/第一节」既不能改名也不能增删（全仓无入口），却占据视觉层级和统计行。作者被迫理解一套自己用不上的概念。
5. **七个「生成」入口挤在一页，语义靠猜。**
   AI 生成大纲（全书，替换）/ 为本卷生成大纲（替换本卷）/ 续排本卷 n 章（追加，出现两次）/ 生成本卷（这是生成**正文**！）/ 生成本章（正文）/ 优化大纲（润色单章章纲）/ 顶栏写下一章（正文）。字面高度相似、后果差异巨大（替换 vs 追加 vs 花钱写正文），且散在三个组件里。
6. **「生成本章」会写错章。**
   见 2.3 表：旧面板的每章「生成本章」按钮因 stale state + `findWriteNextChapter` 的「之后第一个未写章」语义，可能对**被点章的下一章**弹写前对话框。这是能直接制造「它到底在干嘛」体感的缺陷（`page.tsx` 的 `onGenerateChapter` 与 `src/lib/daily-flow.ts` 的 `findWriteNextChapter`）。
7. **两套写入心智模型同页并存，且草稿闸有丢产物缝。**
   手工加章/改字段=直写（`markAuthorCanonEdit`）；AI 排纲=草稿→`DiffConfirmGate` 弹窗确认。作者在同一页一会儿被弹 diff 闸、一会儿直接生效。叠加 P0 复查 H2：提案补丁只在 React 状态里，弹窗期间刷新则花钱生成的大纲**永久丢失**，只留一条打不开的「待确认提案」横幅——这会被作者理解为「AI 生成了但不知道去哪了」。
8. **卷的「结构管理」和「运营仪式」混在大纲页。**
   `VolumesPanel` 同时承担：分卷结构（加卷/排序/删卷）、排纲入口、批量写正文入口、卷摘要生成、过卷向导、弧线目标/出卷局面三个文本框。过卷向导（`VolumeCloseWizard`）还会在批量任务结束时**自动出现在大纲页顶部**。这些是「写到卷尾才需要」的低频仪式，却常驻在「每天要看」的大纲页。
9. **批量标签这类低频工具占据页面中部。**
   `OutlinePanel` 的「批量标签」卡（全选/清空/追加语义说明）横在总览卡与章节目录之间，进一步稀释主任务。
10. **空书路径三岔口。**
    新书进大纲页：上面「新增第一章」（手工直写），下面「AI 生成大纲」（走闸），顶栏「写下一章」（报错后又跳回本页）。空态文案说「可以先手工占一章，再让织卷起草」，但「让织卷起草」的按钮不在眼前，在需要滚动的旧面板里。三个入口没有一个被标为「推荐从这里开始」。

一句话诊断：**S4 只交付了「树的皮」，编辑的「肉」还留在旧面板里，而旧面板没有按 S8 的精神从大纲区拆走**。作者看到的是新旧两代界面的物理叠加。

## 四、整改方向：抄 OpenWrite 的交互，穿幻想作家的衣服

原则：**模仿的是交互结构（一棵树、一个就地可编辑的详情、一次点击开写、生成入口收敛、默认停在推荐章），不是它的技术栈或像素**。所有文案沿用本仓已有词汇（织卷/落墨/写下一章/确认闸）。

### 4.1 目标形态（一屏说清）

```text
大纲工作区 = 左树 + 右详情，再无第三块
├─ 左树
│   ├─ 统计行：n 卷 · n 章 · n 已写（幕/节只在真实存在非默认组时才计入显示）
│   ├─ 动作行：+新增卷 ｜ AI 排纲 ▾（全书重排 / 本卷重排 / 续排本卷 n 章，全部走既有确认闸）
│   ├─ 搜索 + 全部/待写/已写（按整枝过滤，空组头随枝隐藏）
│   └─ 节点行：卷（可改名）→ 章（✓/○）；默认「第一幕/第一节」不渲染
└─ 右详情（选中章）
    ├─ 面包屑：第一卷 / 第 4 章
    ├─ 标题行内可编辑 ｜ 待写/已写徽标 ｜ 大纲 n 字 ｜ 正文目标 n 字（读 settings/wordTargets）
    ├─ 摘要、关键情节点、章末钩子、节奏备注、标签、出场人物 —— 就地编辑（搬自旧 OutlinePanel）
    └─ 动作：写这一章（主按钮，弹 WriteNextDialog）｜ 新增同级章 ｜ 优化大纲 ｜ 删除 ｜ 查看正文
```

### 4.2 隐藏 / 合并 / 改名清单

| 现状元素 | 处置 | 说明 |
|---|---|---|
| `OutlinePanel` 整体（挂在大纲区 `extra`） | **从大纲区移除** | 其章编辑器六字段搬进新树详情；「重新生成大纲/续排」收进「AI 排纲」菜单；拖拽排序 P1 再回到树上；「批量标签」迁到 工具与设置→标签（或大纲页一个折叠抽屉），不再常驻 |
| `VolumesPanel` 整体（挂在大纲区 `extra`） | **从大纲区移除** | 加卷=树顶「+新增卷」；卷改名=树上行内编辑；卷摘要/弧线目标/出卷局面/过卷向导=选中**卷节点**时的详情面板（树的详情本来就该分层级），或迁到工具页；「生成本卷」（批量正文）归位到 工具与设置→批量任务（那里已有同能力入口） |
| `VolumeCloseWizard` 自动插入大纲页顶部 | **改为卷节点详情内出现**，或维持自动但放在正文/总览的提示条 | 过卷是写作里程碑事件，不是大纲结构操作 |
| 「用此章创建正文」 | **改名「写这一章」并接真行为**：打开 `WriteNextDialog(该章)` → `runWritePipeline` | 与顶栏「写下一章」共用管线；已写章则文案变「查看正文」 |
| 「原文定位」 | **改名「查看正文」**（跳正文页并定位该章），或在「写这一章」落地后直接删除 | 消灭同义双按钮 |
| 「生成本章」（旧面板按钮） | 随旧面板移除；新详情「写这一章」必须**精确指向被点章**（不复用 `findWriteNextChapter` 的「下一章」语义，也不经由 stale 的 `selectedChapterId`） | 顺手消灭 2.3 的写错章缺陷 |
| 默认「第一幕/第一节」组头 | **不渲染**（树只显示 卷→章）；`outlineTree` 数据结构原样保留 | 数据层四级树是对的，UI 在作者真的能创建幕/节之前不展示。幕/节的增删改名是 P1 独立切片，做之前不给名词 |
| 「新增第一章」空态 | 保留，但空态卡同时给「让织卷排大纲」按钮（触发既有 `generateOutline`），并一句话说明两条路的区别 | 消灭三岔口：两个按钮 + 一行说明，推荐路径放主按钮位 |
| 统计行「n 幕 n 节」 | 隐藏（同默认组头处置） | 与显示层一致 |
| 「续排本卷 n 章」双入口 | 收进「AI 排纲」菜单，仅此一处 | 章数默认取 `settings.chapterCount`，菜单内可改 |
| 详情「目标见生成参数」 | 就地显示数字：正文目标 = 章目标字数（`settings.length` 换算或 `wordTargets`） | 抄 OpenWrite 的「正文目标 6,000 字」体感 |

### 4.3 从零作者路径（整改后，7 步）

1. 新建书 → 资料库补一句话前提（引导卡已有）；
2. 进「大纲」：空态卡二选一——点**「让织卷排大纲」**（推荐）或「新增第一章」手工起步；
3. 织卷返回全书章纲 → `DiffConfirmGate` 看 diff → 确认写入，树上出现全部章节点；
4. 点任一章 → 右侧**就地改**标题/摘要/钩子（直写，记作者痕迹）；
5. 点详情主按钮**「写这一章」**→ `WriteNextDialog` 写前检查 + 本章指导 → 开始写；
6. 落墨走 起稿→审稿→结算，完成后树上该章自动打勾；
7. 次日打开：顶栏「写下一章」或树上下一个 ○ 章，重复 4–6。写到卷尾时，卷节点详情出现过卷向导入口。

每一步只有一个明显的下一步，这就是 OpenWrite 「不混乱」的全部秘密。

### 4.4 明确不抄的东西

- **Python / 文件真源**：OpenWrite 以 `src/outline.md` 为真源、增量写回 + Git 存档 + revision 冲突检查。我们的真源是 `project.outline.chapters` + `outlineTree` 视图（IndexedDB，防抖落库 + 自动备份），**数据层没有病，不迁移存储**。不引入 outline.md 落盘、不做 Git 存档。
- **Vditor / Markdown 即时渲染编辑器**：详情面板用现有 textarea/输入组件即可，编辑器引擎仍按 1.6 方案第八节留 P2。
- **四级层级的完整 CRUD 起步就做**：OpenWrite 的幕/节承载弧线字段（目的/戏剧结构/情感走向），是它规划提示词的输入。我们的提示词管线还没消费这些字段，先把 UI 收敛到 卷→章；幕/节编辑与「弧线字段进 packet」捆绑成 P1 独立切片，避免再造一层装饰。
- **服务端推荐算法**：`outline.recommendation` 的等价物我们已有（`findWriteNextChapter`），不需要新服务；只需让大纲页进入时默认选中它（要修正 3.6 所述语义后再复用）。
- **像素克隆**：截图的排版字号、徽标样式、删除按钮红色细节不追；沿用 FantaWriter 现有 token（`--border-soft`、`btn` 体系、`studio-tree-row`）。
- **每层级大纲字数目标的设置项**（OpenWrite 的 `outline_volume_words` 等四个档位）：P2 再议，先把「正文目标」一个数字亮出来。

## 五、给后续编码 Agent 的实施切片

> 每片独立可合、可测，按顺序做但不强依赖。只给症状与完成判据，不给逐行改法——**动手前请先自行核对现状**（尤其 `page.tsx` 大纲区装配段与 `OutlineWorkspace` 的 props 面），本文若与代码不符以代码为准。全部切片均不改 schema、不动 `outline-tree.ts` 的数据结构与同步算法。

- **O1 · 大纲页减法（最高优先）**
  症状：大纲工作区滚动可见两份章节列表与 30+ 按钮（第二节的装配图）。
  做法边界：从 `page.tsx` 的大纲区 `extra` 移除 `OutlinePanel` / `VolumesPanel` / `VolumeCloseWizard` 常驻挂载；它们承载的能力按 4.2 表归位（本切片内至少保证：AI 排纲三入口收进树顶菜单、批量正文入口指向工具页既有位置、其余暂不可达的能力在 O2/O3 前**不得静默丢失**——若归位未完成则本切片先不合入，避免中间版本功能失联）。
  完成判据：大纲页 DOM 中章节列表唯一；页面上每个「生成」类按钮语义互斥（重排/续排/写正文三类各一处）；`npm run lint`、`npm test` 过；手测旧项目打开大纲页无报错、原有卷摘要/弧线目标数据在新家可见可改。
- **O2 · 详情面板就地编辑**
  症状：新树详情只读，改摘要要去楼下旧面板找同一章（三.2）。
  完成判据：选中章后，标题/摘要/关键情节点/章末钩子/节奏备注/标签/出场人物全部就地可编辑，落库路径与旧面板一致（直写 + `markAuthorCanonEdit`）；提供删除章（沿用旧 confirm 文案与账本告警语义）；连续键入不丢焦点、不整页重渲染卡顿（百章书手测）。
- **O3 · 「写这一章」真按钮**
  症状：「用此章创建正文」「原文定位」行为相同且都不开写（三.3）；旧「生成本章」会写错章（三.6）。
  完成判据：详情主按钮对**被选章本身**打开 `WriteNextDialog`（含写前检查），确认后走 `runWritePipeline`；已写章显示「查看正文」跳正文页定位；单测覆盖「点第 3 章（未写，第 4 章也未写）→ 对话框标题是第 3 章」；顶栏「写下一章」行为不变。
- **O4 · 假层级与空壳收敛**
  症状：不可操作的「第一幕/第一节」常驻；筛选后留空组头；统计行计入幕/节（三.4、2.4）。
  完成判据：默认组（`createDefaultAct` 生成且未被作者改名）在树与统计行均不显示；搜索/筛选按整枝隐藏空卷；`outlineTree` 序列化数据与既有单测（`studio-v3.test.ts` 树部分）不变；若未来存在非默认幕/节数据（手工构造 JSON 导入）则如实显示——「隐藏默认组」而非「隐藏层级」。
- **O5 · 空态与推荐章**
  症状：空书三岔口无推荐；进页默认选中「大纲第一章」而非「下一个该写的章」（三.10、`effectiveSelectedId` 回落逻辑）。
  完成判据：空态卡「让织卷排大纲」为主按钮、「新增第一章」为次按钮、各配一句话说明；有大纲时进入大纲页默认选中下一个待写章（复用修正后的推荐语义）并滚动到可见；空书顶栏「写下一章」的报错文案指向空态卡的两个按钮。
- **O6 · 卷节点详情与过卷仪式归位（P1，可后置）**
  症状：卷的运营操作与大纲结构混排（三.8）。
  完成判据：树上选中卷节点时详情显示卷字段（标题/摘要/弧线目标/出卷局面）与「AI 生成本卷摘要」「过卷向导」入口；`VolumeCloseWizard` 不再自动插在章详情上方；卷尾提醒仍可达（`DailyStatusBar` 的既有跳转保留）。
