# 幻想作家(常规版)迭代优化方案

> 面向作者本人:一个人维护 + 用它写《醉词》群像长篇(五卷,原作焕新)。
> 本文只做审查与规划,不改任何业务代码。所有结论均以当前 master(`36f5145`)代码为准,点到文件与函数。

---

## 一、这套架构实际怎么跑

### 1.1 一次「生成本章」的完整链路

1. **前端组装上下文**(全部在浏览器/Electron 渲染进程):
   - `src/app/project/[id]/page.tsx` 的 `generateChapter()` 调 `buildPreviousContext()`(`src/lib/api.ts`)→ `buildMemoryPack()`(`src/lib/memory-pack.ts`),拼出「角色状态卡 + 前 5 章摘要 + 上章结尾 1000 字 + 未回收伏笔 + 关键词命中的世界观条目」的 `priorBlock`;
   - `attachOriginalContext()`(`src/lib/original.ts`)把整份原作底稿 `project.original.text` 和全部锁定设定 `project.canon` 原样塞进请求体;
   - 整个 project 的人物、背景、大纲、设置也全量进请求体,POST 到 `/api/generate`。
2. **服务端组装提示词**(`src/app/api/generate/route.ts`):
   - `assemble()`(`src/lib/prompts/registry.ts`)按 mode 分发:system = `CRAFT_SYSTEM`(`src/lib/prompts/craft.ts`)+ `GENERAL_CHAPTER_SYSTEM`(`src/lib/prompts/general.ts`),user = `generalChapterUser()`;
   - `injectOriginalGrounding()`(`src/lib/original.ts`)若有原作:system 追加「原作焕新(硬性)」规则,user 最前面插入锁定设定 + 按关键词摘出的原作片段(上限 7000 字,`selectOriginalExcerpts()`);
   - route 里再用 `user.replace(/## 正文要求/, prior + "\n\n## 正文要求")` 把记忆包字符串替换进去;
   - `chatCompleteStream()`(`src/lib/ai.ts`)以 temperature 0.9、max_tokens 8192 调 OpenAI 兼容接口(`DEEPSEEK_BASE_URL`,即 ZenMux 等中转),SSE 流回前端。
3. **落盘**:前端收完流,写回 `project.chapters[]`,`useProjectStore` 防抖 280ms 后 `upsertProject()` → `src/lib/storage.ts` 写 IndexedDB(`fantasy-writer`)+ localStorage,并按 `brandRenameComplete` 标志**双写旧库** `erotic-novel-studio`;随后异步发一个 `chapter_summary` 请求生成本章摘要供后续衔接(失败静默吞掉,`.catch(() => {})`)。
4. **全书队列**:`runBookJob()`(page.tsx)在前端串行逐章调 `generateChapter()`,可暂停/跳过/重试,job 状态序列化在 `project.bookJob`。**队列活在页面里**——关掉窗口/刷新即停,靠 `prepareJobForResume()` 续跑。
5. **桌面壳**:`electron/main.cjs` 把 Next standalone 作为子进程跑在 `127.0.0.1:17831`(写死,`ENS_PORT` 可覆盖),窗口 loadURL。更新器读 GitHub Releases latest(`electron/github-release.cjs`,默认仓 `qingyou0420/FantaWriter`),失败回退扫本地目录。密钥在 `%APPDATA%\fantasy-writer\config.env`,由 `src/lib/ai.ts` 的 `APP_CONFIG_PATH` 机制读入,不进前端包。发版走 `.github/workflows/release-win.yml`,有「standalone 里出现 .env 即中止」的防泄漏闸。

### 1.2 最大的结构性问题(按影响排序)

**① 提示词双份漂移**。`src/lib/prompts.ts`(1037 行,旧双台时代)和 `src/lib/prompts/general.ts`(405 行,拆台后新写)存在大面积重复:`buildChapterUserPrompt` vs `generalChapterUser`、`buildOutlineUserPrompt` vs `generalOutlineUser`、`buildRewriteUserPrompt` vs `generalRewriteUser`……而 `registry.ts` 两边混用:outline/chapter/rewrite 走 general.ts,**continue/scene_plan/scene_chapter 却走 prompts.ts 的旧函数**。改一处提示词很容易漏另一处;prompts.ts 里还残留成人版遗迹(`ADULT_SYSTEM` 别名、`buildExpandBackgroundUserPrompt` 里的「欲望走向」「暧昧、禁忌、甜虐」文案——这几个函数已是死代码但仍在导出)。

**② 记忆包走「前端拼字符串 → 服务端正则替换」的脆弱通道**。`route.ts` 第 140 行用 `user.replace(/## 正文要求/)` 注入 prior block:若 general.ts 里这个标题哪天改了字,注入就**静默失效**,没有任何报错。且同一份信息有两条路径(`priorBlock` 整块 vs `previousSummaries` 等散字段),`buildPriorContextBlock()` 里 `priorBlock` 优先短路,散字段实际是摆设。

**③ 上下文注入无预算、大量重复**。单章 prompt 里:人物设定全量出现一次(`formatCharacters`,每人全字段),角色状态卡里**再重复一遍**同样的人物字段(`buildCharacterStateCard`);全书大纲每章 summary 全量列出(五卷几十章时这块会非常大);原作摘录最多 7000 字再压最前。没有任何 token 预算控制,真正要写的「当前章节」信息被淹没在末尾——这是生文质量问题的最大结构根源(详见第二节)。

**④ 拆台遗留的双写与死字段**。`storage.ts` 按 `brandRenameComplete` 标志双写旧库 `erotic-novel-studio:*`;`types.ts` 里 `eroticLevel`、`eroticNote`、`EROTIC_LEVEL_LABELS` 仍在(注释说明是导入旧 JSON 兼容,但 `parseSettingsFields` 还在解析 `eroticLevel`)。公开仓的新用户根本没有旧库,这套双写只增加维护面。

**⑤ 队列跑在渲染进程**。全书生成期间不能关窗口;Electron 下这尚可接受(单机单人),但值得知道边界。

其余(单一 God route、payload 全是 `Record<string, any>`)属于可忍受的单人项目债,不列为必改。

## 二、为什么生文/润色「差强人意」

逐条对着代码说:

### 2.1 篇幅约束形同虚设
- 章节篇幅只有一行软文案:`LENGTH_LABELS`(types.ts)的「长篇(约3000–5000字/章)」经 `formatSettings()` 混在参数区一行带过。**没有硬性最低字数、没有生成后校验、没有不足自动续写**。中转模型对「约 X 字」极不敏感,通常 1500–2500 字就收尾——这直接就是「扩写效果差强人意」的第一原因。
- `keyPoints` 只是一行分号串,没有要求模型按节拍展开;分场景生成(`scene_plan`/`scene_chapter`)本可解决这个问题,但每场景又限死「约 400–1500 字」且入口藏在正文页折叠区,和一键队列是两条互不相通的路径(队列只走整章模式)。

### 2.2 信息重复挤占,重点后置
- 如 1.2③:人物设定注入两遍(设定块 + 状态卡),群像书人物一多,重复部分轻松吃掉几千 token;全书大纲全量列出;而「当前要写的章节」「正文要求」在 user 末尾。模型注意力被前面的静态设定稀释,写出来平均化、不聚焦本章冲突。
- **没有「本章出场人物」的概念**:`formatCharacters(characters)` 永远全量。写群像时,一章只涉及 3 个人却注入 15 个人的完整设定,既费钱又把不出场的人物「召唤」进正文(人物乱入正是典型症状)。

### 2.3 原作焕新:检索粗、事实与文笔耦合
- `excerptKeysFromPayload()`(original.ts)把章节标题/摘要/keyPoints 按 `[\s,，、;；\n]+` 切分,**长度 ≥2 的中文片段全部当检索词**——中文没有空格,切出来的是「他终于在渡口见到了那匹白马」这类整句或长短语,`indexOf` 精确匹配几乎必不命中;命中的反而是「清溪」这类 canon 名字(靠 `canonSearchKeys`)。结果是 7000 字摘录额度实际由「开头 1400 字 + 每个锁定名前 3 次出现 ±280 字」构成,**与当前要写的章节内容基本无关**。
- 更隐蔽的冲突:《醉词》原稿是初中写的,文笔恰恰是要焕新掉的部分。但 `ORIGINAL_SYSTEM_RULE` 说「扩写/润色旧稿……原作摘录(须忠实)」,又同时要求「必须严格模仿学习文风指南」——**「忠实原作」没有限定为忠实事实/情节,模型会连原稿的稚嫩文笔一起忠实**。system 里两条硬性指令打架,输出摇摆。
- 锁定设定的违规检测只认「不是X」句式(`forbiddenClaimsFromStatement` 的正则),且只在**人设生成**时同步拦截(`assertCharactersRespectCanon`);`detectCanonViolations()` 能检查正文却没有任何调用方(只有测试在用)——正文写崩锁定设定时不会有任何提示。「清溪是马」教训抄掉了硬编码,但通用检测其实只覆盖了一半场景。

### 2.4 文风学习:学了不用全
- `learn_style` 产出的 `fingerprints`(3–5 句指纹例句)**只存库、只在 StyleLearnPanel 展示,从不注入生成提示词**——`formatSettings()` 只用 `learnedStyleGuide`。对模仿文风来说,少量具体例句比 300–600 字抽象守则有效得多,这是白白扔掉的最有效素材。
- 风格指南放在 user 的「写作参数」区,而不是 system。system 里只有一句泛泛的「若提供了固定学习文风指南必须模仿」(craft.ts 第 3 条),真正的指南内容在 user 中部,权重不足。

### 2.5 润色/续写通道先天残缺
- **润色(rewrite)不带记忆**:`runRewrite()`(ChaptersReader.tsx)只传 `selectedText + fullContext`(且 `generalRewriteUser` 只取 fullContext 前 **2500 字**——改第 4000 字处的段落时上文根本看不见)、人物、背景、参数;**不带前情摘要、状态卡、伏笔、世界观、上章结尾**。润色一段涉及前章伏笔的文字时,模型是盲的。
- expand 模式没有目标长度(「加长但不跑题」——加多长?),polish/expand/shorten 共用 temperature 0.75、maxTokens 4096,选中 3000 字想扩到 6000 字会被 token 上限掐断。
- 续写(continue)倒是带了记忆包,但输出被写死「约 400–1200 字」(`buildContinueUserPrompt`,prompts.ts 第 782 行),对长篇扩写来说太碎。

### 2.6 长程记忆天花板:5 章 + 0 卷
- `buildMemoryPack()` 只回看**最近 5 章摘要**(每章 120–250 字)+ 上一章末 1000 字。写到第三卷时,第一卷发生了什么全靠 `plotThreads`(手工维护的伏笔条)和人物静态设定。
- **分卷有 `summary` 字段(`Volume.summary`,types.ts)但全链路没有任何 prompt 读它**——`memory-pack.ts` 里 grep 不到 volume/卷。五卷群像的卷级弧线,系统性缺席。
- 章摘要生成失败静默吞掉(page.tsx `.catch(() => {})`),缺摘要的章在记忆包里退化成正文前 200 字,且 UI 没有「重新生成摘要」入口,坏一章衔接坏一串。
- 世界观检索(`selectLoreForPrompt`,lore.ts)是纯 `includes` 命中,依赖作者把 keys 填准——机制合理,但 keys 为空的条目永远不进 prompt,UI 没提醒。

### 2.7 大纲:一次性生成对五卷长篇不成立
- `generateOutline()` 一次要求全书大纲,`maxTokens 4096`——三十章 JSON 必然截断,解析失败就把原始文本丢给用户手动整理(route.ts outline 分支的 catch)。`chapterCount` 提示 3–12 章,本质是为短中篇设计的。
- 分卷是**后置的组织工具**(把已有章拖进卷),不是**生成时的规划单位**:没有「按卷生成大纲」——想给第三卷排 15 章,只能生成后手工挪。

### 2.8 采样参数一刀切
- chapter/continue 固定 temperature 0.9——中转模型高温更容易水词、口癖循环;rewrite 0.75。全部写死在 route.ts,没有任何 UI 或配置入口。`DEEPSEEK_THINKING` 是全局环境变量,不能按任务开(大纲/一致性检查适合开推理,正文不一定)。

## 三、迭代项(按优先级)

原则:先改「每天写《醉词》立刻有感」的,机制类靠后,债务类最后。每项标注涉及文件与完成标准(DoD)。

### P0 —— 立刻做(直接改善每一章的质量)

**P0-1 章节篇幅硬约束 + 不足自动续写**
- 改动面:`src/lib/prompts/general.ts`(generalChapterUser 的「正文要求」加显式目标字数区间与「禁止提前收尾/总结式结尾」),`src/lib/types.ts`(LENGTH_LABELS 对应到数字区间常量),`src/app/project/[id]/page.tsx` 的 `generateChapter()`(生成完测字数,低于下限自动追加一轮 continue 拼接,最多一次,或在章卡上给「一键补足」按钮)。
- DoD:长篇档连续生成 10 章,≥90% 的章 ≥3000 字;不足章有明确 UI 提示或已自动补足;`npm test` 加对应的 prompt 文案断言。

**P0-2 「本章出场人物」+ 去重注入**
- 改动面:`src/lib/types.ts` 的 `OutlineChapter` 加可选 `castIds: string[]`;大纲面板(OutlinePanel)与正文页给个多选;`generalChapterUser` 只全量注入本章 cast,其余人物降级为一行名片(姓名+定位+与 cast 的关系);`buildCharacterStateCard`(memory-pack.ts)去掉与人物设定块重复的静态字段,只保留「近期状态线索」。未选 cast 时保持现状(全量),不破坏旧项目。
- DoD:选了 3 人 cast 的章,prompt 里其余人物每人 ≤1 行;单元测试覆盖;实际生成时不再出现明显的「不出场人物乱入」(自评 3 章)。
- 这是群像书性价比最高的一刀。

**P0-3 原作焕新:事实/文笔解耦 + 中文检索修正**
- 改动面:`src/lib/original.ts`:
  1. `ORIGINAL_SYSTEM_RULE` 明确「忠实的是情节、身份、事实;文笔、节奏、描写以文风指南/写作参数为准,允许并鼓励重写原句」;
  2. `excerptKeysFromPayload()` 停用整句分词——只用 canon 名称+别名、人物名(characters[].name/aliases)、lore keys 作为检索词;章摘要不再切词进 keys;
  3. 每个关键词命中窗口从「前 3 次出现」改为可按章节序号推进(简单做法:按 `chapter.order / 总章数` 比例定位到原文对应区段再就近取窗口),让第四卷的章摘到原文后半段。
- DoD:`original.test.ts` 加用例:给定「清溪」锁定 + 第 N 章 payload,摘录命中原文相应区段而非只有开头;生成一章对照,输出文笔明显跟指南而非原稿(人工判)。

**P0-4 文风指纹句注入 + 指南提权**
- 改动面:`src/lib/prompts.ts` 的 `formatSettings()`(或迁到 general.ts,见 P2-1):learned 模式下把 `fingerprints` 以「风格例句(模仿其气质,勿照抄)」列进指南块;`GenerationSettings` 加 `learnedStyleFingerprints` 快照字段(applyLearnedStyle 时一并存,page.tsx);`registry.ts` 的 `assembleGeneral()` 把学习文风指南从 user 挪进/复制进 system 尾部。
- DoD:learned 模式生成的请求,system 或 user 顶部含 styleGuide 与 ≥3 句指纹;assemble.test.ts 断言;A/B 各生成同一章 2 次,自评贴合度提升。

**P0-5 卷摘要进记忆包 + 章摘要可修复**
- 改动面:`src/lib/memory-pack.ts`:`buildMemoryPack()` 接收 volumes,注入「本卷主题与已完成卷的一句话总结」(数据就用 `Volume.summary`,先由作者手写,VolumesPanel 已有编辑入口);`page.tsx`/ChaptersReader:章摘要生成失败不再静默,章卡显示「无摘要」并给「重新生成摘要」按钮。
- DoD:memory-pack 单测覆盖卷摘要注入;删掉某章 summary 后 UI 可见且一键可补。

### P1 —— 接着做(机制补强)

**P1-1 按卷生成大纲(层级大纲)**
- 改动面:新增 `outline_volume` mode(route.ts + registry.ts + general.ts):输入 = 卷主题/卷摘要 + 前卷终局状态 + 本卷期望章数,输出该卷章节列表并自动挂 `volumeId`;OutlinePanel/VolumesPanel 给「为本卷生成大纲」按钮;outline 请求 maxTokens 提到 8192。保留现有整书大纲入口给短篇用。
- DoD:五卷项目可以逐卷排 10–15 章不截断;新章 volumeId 正确;`volumes.test.ts` 扩展。

**P1-2 润色/续写带记忆**
- 改动面:ChaptersReader 的 `runRewrite()` 传 `buildPreviousContext()` 结果;`generalRewriteUser` 接收并注入 prior block,fullContext 改为「选区前后各 N 字」的滑窗而非固定前 2500 字;expand 模式加目标倍数/字数参数(UI 一个下拉:1.5×/2×/自定);continue 的「400–1200 字」上限改为跟随 length 档。
- DoD:改写第 5000 字处的段落时 prompt 含选区上下文与前情摘要;expand 2× 实测产出 ≥1.6×。

**P1-3 正文 canon 后置检查(不阻断)**
- 改动面:`generateChapter()` 完成后前端调已有的 `detectCanonViolations(text, canon)`(original.ts,纯函数,前端可直接跑),命中则在章卡挂黄条「与锁定设定可能冲突:……」。不拦截、不重生成。
- DoD:构造「清溪不是马」锁定 + 含「清溪四蹄踏雪」的正文,生成后 UI 出提示;已有测试用例 `original.test.ts:254` 直接复用。

**P1-4 记忆包注入通道去掉正则替换**
- 改动面:`generalChapterUser()` 直接接收 `priorBlock` 参数拼在「当前要写的章节」之前;删除 route.ts 里的 `user.replace(/## 正文要求/)`。顺带把 `buildPriorContextBlock` 的散字段路径删掉(只留 priorBlock)。
- DoD:assemble.test.ts 断言 prior 出现在 user 且只出现一次;route.ts 无 replace 注入。

**P1-5 生成参数可调温度/推理开关**
- 改动面:`GenerationSettings` 加 `temperature?: number`;SettingsPanel 一个滑杆(0.6–1.0,默认维持现值);route.ts 各分支读它;`DEEPSEEK_THINKING` 保持环境变量但在 API 设置页可见其状态(`getEnvDiagnostics` 已回传,补 UI)。
- DoD:改滑杆后请求体温度随之变化(网络面板可验);默认行为不变。

### P2 —— 以后再说(债务与打磨)

**P2-1 合并提示词层**:general.ts 成为唯一来源,把 registry 仍引用的 `buildContinueUserPrompt`/`buildScenePlanUserPrompt`/`buildSceneChapterUserPrompt` 迁过去,删除 prompts.ts 里的死代码(`ADULT_SYSTEM`、旧版 build* 系列、含「欲望走向」文案的函数)。DoD:prompts.ts 只剩 format*/parse* 工具函数;`bannedHits` 扫描全部 assemble 输出为零(已有测试);行为零变化(快照对比)。
**P2-2 移除旧库双写**:`storage.ts` 的 `shouldDualWriteOld()` 恒定 false 化(或把 `brandRenameComplete` 默认置真),保留「启动时读旧库迁移」只读路径一个版本,再删。DoD:新装用户 localStorage/IDB 无任何 `erotic-novel-studio:*` 键;老数据仍可迁入。
**P2-3 清理 erotic 遗留字段**:`eroticLevel`/`eroticNote` 从写路径移除(normalize 读兼容保留一版)。DoD:新建项目序列化 JSON 无 erotic 字样。

### 写《醉词》的操作建议(不改代码就能做)

- 先把五个卷的 `Volume.summary` 手写填掉(每卷 3–5 句:主题、起点状态、终点状态)——P0-5 落地后立即吃到收益,落地前也能当自己的备忘。
- 锁定设定尽量写成「X不是Y」/「X是Z,不是Y」句式,现有 `forbiddenClaimsFromStatement` 只认这个;别名一定填全(乳名、称号)。
- 世界观条目把 `keys` 填满(含别名),空 keys 的条目永远不会进 prompt。
- 拿你最满意的一章(而不只是原稿)喂文风学习,让 styleGuide 描述「想要的文笔」而非「原来的文笔」。

## 四、明确不做的事

1. **不合回双写作台,不做第三台**。`WritingBoard` 保持 `"general"` 单值,`ContentRating` 保持 unrated 死字段(types.ts 注释已写明「禁止据此做第三写作台」——遵守它)。
2. **不把任何密钥/令牌写进仓**。API Key 只在 `.env.local`/`config.env`;GitHub 更新令牌只在本机 `config.env`(main.cjs 现有机制);release workflow 的「Refuse secrets in standalone」闸保留。
3. **不再把任何一部作品的设定硬编码进产品**。「清溪是马」抄掉后,原作焕新保持纯数据驱动(用户粘贴的原文 + 用户锁定的条目),《醉词》专属的东西一律走项目数据,不进 `src/`。
4. **不用 Fable 5(或任何代理)直接改功能代码**——本仓的代码改动由作者自己看着改;本轮及后续规划类任务只产出文档。
5. **不做 RAG/向量库/嵌入检索**。单机单人 + 一本书的规模,关键词窗口检索修好(P0-3)就够;引入向量库是维护负担不是能力。
6. **不换框架、不上服务端数据库、不做账号/多端同步**。IndexedDB + JSON 备份 + 「写进仓库」导出已覆盖需求。
7. **不做自动多轮 agent 式改稿**(生成→自评→重写循环)。费用不可控且中转模型自评不可靠;P1-3 的「检测但不阻断」是上限。
8. **不动打包/更新链路**(除 P2-4 一行端口探测)。GitHub Release 更新刚上线且链路完整(token 不外带 CDN、下载域白名单、文件名校验都有),稳定优先。
