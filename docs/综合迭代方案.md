## 一、现状判断：P0 之后最大的剩余问题

先说清楚哪些**不是**新发现——上一轮《迭代方案》的五个 P0 已落地且复查到位，本文不再重复它们：

- 篇幅硬约束（`length.ts` 数字区间 + 生成后 `chapterBelowMin` 自动续写一次 + 补足按钮）；
- 本章出场人物（`OutlineChapter.castIds` + `formatCharacters` 名片降级 + 状态卡去重）；
- 原作只锁事实（`ORIGINAL_SYSTEM_RULE` 解耦事实/文笔，检索只用名称/别名/lore keys，摘录按 `chapter.order/总章数` 推进原文区段）；
- 文风指纹注入（`registry.ts` 的 `learnedStyleSystemAppendix` 把指南+指纹进 system）；
- 卷摘要进记忆（`memory-pack.ts` 的 `formatVolumeMemory`，缺章摘要可补）。
- 顺带落地的 P1 也确认在：按卷大纲（`outline_volume`）、润色/续写带记忆与选区滑窗（`sliceAroundSelection`）、canon 后置黄条（`detectCanonViolations` 已有调用方，page.tsx:526）、priorBlock 直传不再正则替换。

**P0 之后，剩余问题的重心从「生成质量」转移到了「工程护栏」和「失败时的体验」。** 按影响排序：

### ① 质量门禁是半个的：CI 只跑 vitest，lint 已经悄悄挂了

`.github/workflows/test.yml` 第 16–17 行只有 `npm ci` + `npm test`。`tsc --noEmit` 今天能过纯属上一轮复查修过（e515327），CI 不守着，下次再坏没人知道。更实际的证据：**`npm run lint` 现在就是挂的**——22 个 error：

- `electron/*.cjs`、`scripts/*.cjs` 全部命中 `@typescript-eslint/no-require-imports`（eslint.config.mjs 没有对 `.cjs` 放行 require）；
- `react-hooks/set-state-in-effect` 共 9 处 error（`page.tsx:165`、`AppSettingsMenu.tsx:61,78`、`ChaptersReader.tsx:113,209`、`OutlinePanel.tsx:58`、`StyleLearnPanel.tsx:52`、`ToolsPanel.tsx:91,104`）。

上一轮方案写的「通用底线：npm test 与 npm run lint 全绿（CI 已强制）」其中 lint 部分是错的——CI 从来没跑过 lint。单人项目最怕的就是「以为有门禁其实没有」。

### ② 提示词双层没合，registry 还在两边混用

`src/lib/prompts.ts` 仍有 1086 行，其中 **17 个导出是纯死代码**（已逐个 grep，非测试调用为零）：`ADULT_SYSTEM`、`buildChapterUserPrompt`、`buildOutlineUserPrompt`、`buildRewriteUserPrompt`、`buildExpand/Optimize*UserPrompt` 系列、`buildLearnStyleUserPrompt`、`buildPolishChapterOutlineUserPrompt`、`buildPriorContextBlock` 等。死代码里还躺着成人版遗迹文案（`buildExpandBackgroundUserPrompt` 的「欲望走向」「暧昧、禁忌、甜虐」，prompts.ts:393,397——正是 `GENERAL_BANNED_SUBSTRINGS` 要拦的词，靠「没人调用」而不是「不存在」保安全）。同时 `registry.ts:21–25` 仍从 prompts.ts 引 `buildContinueUserPrompt` / `buildScenePlanUserPrompt` / `buildSceneChapterUserPrompt`——continue/scene 两条链路的提示词和 chapter/rewrite 不同源，改文风注入、改篇幅条款时依旧要记得改两处。

### ③ 一致性检查的提示词模板有实际 bug

`buildConsistencyCheckUserPrompt`（prompts.ts:878–890）输出的 JSON 模板里 **`"severity"` 键写了两次**（883 行「问题简述」、887 行「可选：相关人物名」），本该是 `"character"`。`parseConsistencyResult` 又按 `i.character` 取值——模型照模板输出时 `character` 字段永远缺失，且「severity」被教成了「问题简述」。一致性检查（工具页）的结果因此天然残缺。

### ④ 旧库双写没退场，而且启动镜像**无视开关**

`storage.ts:165–169`：只要新库有数据，`initStorage` 每次启动都 `writeIdbProjects(OLD_IDB_NAME, …)`——**没有** `shouldDualWriteOld()` 判断。也就是说公开仓的全新用户装上「幻想作家」，每次启动都会凭空创建并全量镜像一个叫 `erotic-novel-studio` 的 IndexedDB。`getAutoBackup`/`copyAutoBackupIfNeeded` 的读路径 `openKv(OLD_IDB_NAME)` 同样会把这个空库建出来（IndexedDB open 即建库）。`brandRenameComplete` 默认 true 只关掉了 localStorage 的双写（`lsWriteDual`），IDB 这条最重的没关。这不只是维护面：新用户浏览器里躺着一个旧产品名的数据库，也是尴尬。

### ⑤ 破坏性操作缺护栏，方向还不一致

- **「重新生成大纲」没有任何确认**（顶栏与 `OutlinePanel:227–229` → page.tsx `generateOutline`）：整本大纲替换、章节行重建、`bookJob` 清空。对比之下删单章大纲反而有 confirm——最重的操作护栏最少。
- 正文页「生成本章」调用时传 `force=true`（page.tsx:1393），**跳过**了 425–426 行「该章已有正文，确定覆盖重新生成？」的确认；而大纲页触发同一函数不传 force。同一动作两个入口两种行为。
- 「强制全部重生成」反而连弹两次 confirm（菜单 1041 + `startBookJob` 804）。

### ⑥ 失败恢复弱、错误提示给开发者看

- 单章失败后只有底部红字（`ChaptersReader:1252–1255`），**没有「重试」按钮**，按钮文案仍是「生成本章」；顶栏错误条只有「关闭」。队列错误即停（设计合理）但对中转常见的瞬时 5xx/超时没有任何自动重试。
- 错误文案直出开发语境：`lib/ai.ts:172–174`「…或编辑 .env.local」（桌面用户没有 .env.local）；`formatAiError`（204–208）把 `provider=… model=… base=… key=…(len=…)` 全拼进用户可见 message；`route.ts:443`「未知 mode」；`registry.ts:127–129` 直接抛错误码字符串 `REWRITE_MODE_NOT_ALLOWED`；`export-chapters.ts:277`「没有已完成（status=done）且有正文的章节」；章节状态点 title 是英文 `idle/generating/done/error`（`ChaptersReader:1288`）。
- 桌面壳最典型的「骗人错误」：`electron/main.cjs:177–180`，standalone 子进程**任何**非零退出都弹「常见原因：安装包缺少 node_modules（请用新版安装包重装）」——端口被占、config.env 写坏、杀软拦截都会被归因成装包坏了，引导用户白白重装。

### ⑦ 桌面壳的两个结构性弱点

- 端口写死 17831（`main.cjs:14–15`）且 `waitForServer`（87–116）只要该端口返回任意 HTTP 响应就算「就绪」——被别的进程占用时要么超时、要么**把别人的服务当成自己加载进窗口**。
- `server.log` 每次启动清空（141–145），崩溃后重启一次日志就没了，恰好是最需要日志的时刻。

其余（`route.ts:39` 的 `Body = Record<string, any>` God route、长列表无虚拟化、流式每 delta 全量 setState）仍属可忍受的单人项目债，下文按优先级给出取舍。

## 二、迭代项（按优先级）

每项标注涉及面 [代码/功能/体验/UI]、动机与完成标准（DoD）。原则：先堵「下次改动会不会悄悄坏」的洞，再补「写崩时的体验」，最后做界面整理。

### P0 —— 立刻做

**P0-1 CI 补全门禁：tsc + lint，先把 lint 修绿** [代码]
- 改动面：`.github/workflows/test.yml` 加两步 `npx tsc --noEmit`、`npm run lint`；`eslint.config.mjs` 给 `**/*.cjs`、`scripts/**` 关掉 `@typescript-eslint/no-require-imports`（CommonJS 用 require 是对的，不是违规）；9 处 `set-state-in-effect` 逐个改（多数是「挂载时读 localStorage 初始化」，改成 `useState(() => …)` 惰性初始化或 `useSyncExternalStore`，个别确需 effect 的降级为局部禁用并写明原因）。
- 为什么：这是唯一能替单人作者「盯住回归」的机制。lint 已经挂着没人知道，就是反面证据。
- DoD：`npm run lint`、`npx tsc --noEmit`、`npm test` 三绿；CI 任一失败即红；`release-win.yml` 的 `npm test` 前同样补 tsc（发版更不该带类型错）。

**P0-2 破坏性操作对齐护栏** [体验]
- 改动面：page.tsx `generateOutline` 入口——已有大纲（尤其已有任何章正文）时 confirm，文案写清「将替换全书大纲并清空生成队列，已写正文保留但可能与新大纲脱钩」；page.tsx:1393 去掉 `force=true`，让正文页「生成本章」与大纲页同走 425 行的覆盖确认；「强制全部重生成」去掉一层重复 confirm（保留 `startBookJob` 里那次即可）。
- 为什么：最贵的资产是已写的十几万字和已调好的大纲；现在最重的操作护栏最少、同一动作两入口行为不一致。
- DoD：三个入口手测：重生成大纲有确认且提示后果；正文页对已完成章点「生成本章」出覆盖确认；强制全量只弹一次。

**P0-3 修一致性检查 JSON 模板 bug** [代码/功能]
- 改动面：prompts.ts:883–890 的模板——第二个 `"severity"` 改为 `"character"`，并把首键的说明从「问题简述」改成明确的严重程度枚举（如「high/medium/low 之一」），`parseConsistencyResult` 相应兜底。
- 为什么：这是实际影响输出的 bug，不是风格问题；一致性检查是写群像长篇查「称呼/伤势/关系漂移」的主工具。
- DoD：单测断言模板无重复键、含 `"character"`；实测一次一致性检查返回 issues 带人物名。

**P0-4 失败恢复：单章重试按钮 + 队列瞬时错误自动重试一次** [功能/体验]
- 改动面：`ChaptersReader` 章卡/正文底部，`status === "error"` 时给显式「重试生成」主按钮（复用现有 `onGenerateChapter`，文案区分「生成本章/重新生成/重试生成」）；page.tsx `runBookJob` 的 error 分支——对可判定的瞬时错误（超时、5xx、网络断）自动退避重试一次（间隔几秒），仍失败再停队列；顶栏错误条加「重试」。
- 为什么：走中转写全书队列，夜里跑 15 章遇到一次瞬时 502 就整队停摆，是长篇场景最疼的失败模式。用户能取消（AbortController 链路完整）但不能便捷重试。
- DoD：模拟 5xx：队列自动重试一次成功则继续；连续失败停住且失败章上有一键重试；重试不重复扣「已写正文」（版本栈行为不变）。

**P0-5 错误文案分层：用户话在前，诊断在后** [体验]
- 改动面：`lib/ai.ts` 的 `resolveApiKey`/`formatAiError`——按运行态分文案（`getEnvDiagnostics().isDesktop` 已能判桌面）：桌面说「请在设置 → API 设置里填写密钥」，别提 `.env.local`；`formatAiError` 把 `provider/model/base/key 前缀` 收进一个可展开的「诊断详情」字段（route.ts 已经会带 `env` 回来，前端 Toast/错误条只显示第一句人话）；顺带清理：`route.ts:443`「未知 mode」→「不支持的生成类型（前后端版本可能不一致）」、`registry.ts` 的 `REWRITE_MODE_NOT_ALLOWED` 给中文 message、`export-chapters.ts:277` 去掉 `status=done` 术语、`ChaptersReader:1288` 状态点 title 改中文。
- 为什么：报错是给写小说的作者看的，不是给部署者看的；现在一条鉴权失败能带出 baseURL 和 key 长度，吓人且无用。
- DoD：断网/错 key/超时三种场景，第一行都是不含英文术语的中文指引；诊断信息仍可展开或进日志，排查能力不降。

**P0-6 桌面壳错误分诊 + 端口探测** [体验/代码]
- 改动面：`electron/main.cjs`——启动前探测 17831，被占则 +1 递增（并把实际端口传给 `PORT`/loadURL）；`waitForServer` 改为校验自家健康响应（现成的 `GET /api/generate` 或 `/api/config` 返回 `ok:true` 即可），不再把任意 HTTP 200 当就绪；「内嵌服务已退出」弹窗按可判定原因分诊（`server.js` 缺失/端口占用/config.env 解析失败/其它），不再一律「缺 node_modules 请重装」；`server.log` 改为追加 + 超过阈值截断（保留上次启动的尾部），别在启动时清空。
- 为什么：这是「错误提示骗人」的最大来源；端口误连别人服务是能加载出陌生页面的实际故障。
- DoD：先起进程占住 17831 再启动应用——应用换端口正常起；人为删 server.js——弹窗指向真实原因；崩溃后上次日志尾部仍在。

### P1 —— 接着做

**P1-1 合并提示词层，prompts.ts 退役为工具库** [代码]
- 改动面：把 registry 仍引用的 `buildContinueUserPrompt`、`buildScenePlanUserPrompt`、`buildSceneChapterUserPrompt` 迁入 `prompts/general.ts`（迁移时给 continue 补上 `priorBlock` 直传，与 chapter 同构）；删除上文 ② 列出的 17 个死导出与其测试；prompts.ts 只留 `format*`/`parse*`/`extractJsonObject`/`sliceAroundSelection` 等纯工具（或干脆拆成 `prompts/format.ts` + `prompts/parse.ts`）。
- 为什么：双层是「改一处漏一处」的持续税；死代码里的成人版文案靠没人调用保安全，不如不存在。
- DoD：`rg "buildContinueUserPrompt|ADULT_SYSTEM" src` 只剩 general.ts/测试；`bannedHits` 相关测试保留且全零；迁移前后对同一 payload 的 assemble 输出做快照对比，除刻意改动外零差异。

**P1-2 旧库真正退场** [代码]
- 改动面：`storage.ts`——删掉 initStorage 里无条件的旧 IDB 镜像（165–169）与 persistProjects 里的 `shouldDualWriteOld()` 写路径；旧库**只读迁移**保留一个版本（首次启动新库为空时读旧 IDB/LS 迁入 + `migration-backup-v2` 快照，现有逻辑即是）；`copyAutoBackupIfNeeded`/`getAutoBackup` 的旧库读改为「新库没有才去开旧库」，避免 open 即建库；`lsWriteDual`、`projectTabKeyOld`（`h-novelist:*`）一并清理。
- 为什么：全新用户每次启动被写一个旧产品名的库，见上文 ④；双写代码约百行纯维护面。
- DoD：清空浏览器数据后全新启动，IndexedDB 列表**没有** `erotic-novel-studio`，localStorage 无旧前缀键；构造旧库数据可正常迁入（storage.test.ts 已有基础，补「不再建旧库」断言）。

**P1-3 温度与推理开关进设置** [功能/UI]
- 改动面：`GenerationSettings` 加 `temperature?: number`（正文/续写用，默认 0.9 不变）；`SettingsPanel` 加滑杆（0.6–1.0，注明「中转模型高温易水词」）；route.ts chapter/continue/scene_chapter 分支读它；API 设置页展示 `DEEPSEEK_THINKING` 当前状态（`getEnvDiagnostics` 补一个字段即可，仍用环境变量控制，不做每任务开关）。
- 为什么：温度是正文「水不水」最直接的旋钮，现在全部写死在 route.ts，用户零感知零控制；`.env.example` 里写了 `DEEPSEEK_THINKING=1` 但界面上看不到是否生效。
- DoD：滑杆改动可在请求体里看到；不动滑杆时行为与现在完全一致；assemble/route 测试补参数透传断言。

**P1-4 记忆窗口分层：远章靠卷摘要，近章靠章摘要，卷摘要可一键生成** [功能]
- 改动面：`VolumesPanel` 加「AI 生成本卷摘要」——用该卷各章 `summary` 拼请求（新 mode `volume_summary`，route.ts + registry + general.ts，非流式低温），产出写回 `Volume.summary` 前给编辑确认；`memory-pack.ts` 维持「最近 5 章详摘」但当当前章与某已完结卷距离超出窗口时，确保该卷摘要已在 `formatVolumeMemory` 注入（现状已注入已完成卷，缺的是摘要**从哪来**——现在全靠手写）。
- 为什么：五卷群像写到第三卷，第一卷细节只能靠手写卷摘要撑；「写完一卷点一下生成摘要」比要求作者手写 5 段总结现实得多。这是 P0-5（卷摘要进记忆）落地后顺理成章的下半步。
- DoD：一卷 12 章各有 summary 时，一键产出 100–200 字卷摘要且可编辑保存；memory-pack 测试补「远卷用卷摘要、近章用章摘要」的组合断言。

**P1-5 伏笔回收辅助：摘要顺带盘点线索** [功能]
- 改动面：`buildChapterSummaryUserPrompt`（prompts.ts:841–852）已要求写「未解冲突与可回收伏笔」，但只进自由文本。改为 `chapter_summary` 请求把当前未回收 `plotThreads` 标题列表一并传入，要求额外输出一行「触及的伏笔：A、B」；前端解析后在章卡与伏笔面板给「本章触及」标记，作者点一下即可把线索置为 resolved（仍是手动确认，不自动改状态）。
- 为什么：伏笔板现在是纯手工台账，写到几十章后「哪些线该收了」全凭记忆；生成摘要时模型反正读了全文，顺带盘点几乎零成本。
- DoD：构造含伏笔关键词的章，摘要响应带触及列表且 UI 可见；不改 plotThreads 数据结构，误报只是多一个可忽略的标记。

**P1-6 信息架构减负：12 tab 收敛，正文页给参数快捷入口** [UI]
- 改动面（page.tsx 的 `TABS/STAGES` + 相关面板）：
  1. 「进度」并入「工具」（ToolsPanel 顶部本就嵌了同一个 `ProgressDashboard`，独立 tab 纯重复）——12 减到 11；
  2. 「本书标签」并入「生成参数」页（一屏放得下，标签本质就是生成参数）——减到 10；
  3. 「原作焕新」tab 仅在 `project.original || project.canon?.length` 时显示，从零项目在设定页给一行「挂载原作底稿…」入口——群像新书用户不再被第一个 tab 迷惑；
  4. 正文页侧栏加「篇幅/文风/温度」当前值一行摘要，点击直达生成参数 tab——从正文改篇幅从 3 次点击降到 2 次且不迷路。
- 为什么：审查确认 12 tab 里两处纯重复、一处错位（原作焕新永远占设定第一位）；「生成参数藏在设定末位」是从写作现场调参的主要摩擦。

**P1-7 空状态与首章引导** [体验]
- 改动面：项目页新建后（无人物名、无背景梗概、无大纲时）在当前 tab 顶部给一张「开写四步」卡：人物 → 背景 → 生成大纲 → 生成第一章，完成项打勾，可关闭（复用 `EmptyState` 风格；状态存 localStorage）；`ChaptersReader:1259`「选择左侧章节」与各裸空白面板统一接 `EmptyState` 并带一个行动按钮（如世界观空态给「新建条目」）。

## 三、明确不做的事

1. **不合回双写作台、不做第三台。** `WritingBoard` 保持 `"general"` 单值；`ContentRating` 维持 unrated 死字段（types.ts 注释已写明，遵守它）。H 版已搁置，本仓不为它留活口。
2. **不把任何一部作品写死进产品。** 《醉词》的卷摘要、锁定设定、文风档案一律走项目数据；`src/` 里不出现任何作品专属常量（「清溪是马」的教训已抄掉，保持住）。
3. **不把密钥/令牌写进仓库。** API Key 与 GitHub 更新 token 只在本机 `config.env`/`.env.local`；release workflow 的「Refuse secrets in standalone」闸保留；`.env.example` 只放占位符。
4. **不用 Fable 5（或任何代理）直接改功能代码。** 本文及后续规划类任务只产出文档；`src/`、`electron/`、打包脚本的改动由作者自己动手、看着 diff 合。
5. **不上向量库/RAG/嵌入检索。** 单机单人一本书，名称关键词 + 区段推进的检索（P0 已修好）够用；向量库是维护负担不是能力。
6. **不换框架、不上服务端数据库、不做账号/多端同步。** IndexedDB + JSON 备份 + 导出到文件夹已覆盖需求。
7. **不做自动多轮 agent 改稿循环**（生成→自评→重写）。费用不可控、中转模型自评不可靠；canon 后置检测「提示不阻断」就是上限。
8. **不重构更新链路。** GitHub Release 更新刚上线且 token 处理、下载域白名单是对的；只做 P2-4 那类局部收紧，不换 electron-updater、不做增量更新。
