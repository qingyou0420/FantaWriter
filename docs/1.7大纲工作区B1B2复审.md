## 〇、结论：**可以合并**

B1、B2 两个 blocker 均已按判据消除，补丁未引入新的阻断性缺陷。归主人裁量合并与打包。下述三条观察均不拦截。

## 一、B1（过卷向导锁死）—— 已消除

对照原判据逐条核：

1. **只在打开那一刻定位一次**：新 `shouldSnapToWizardVolume(prev, next)`（`outline-focus.ts`）仅当向导 id 从空/别的卷变为当前卷时返回 true；`page.tsx` 进页 effect 用 `prevWizardIdRef` 记忆上一拍，snap 后不再重复拽选中态。
2. **落库不再触发拽回**：effect 依赖从 `[workspace, project, volumeWizardId]` 改为 `[workspace, project?.id, volumeWizardId]`，键入防抖落库产生的新 `project` 引用不会重跑该 effect——原 B1 的根因（每次落库 `setSelectedVolumeId(volumeWizardId)`）已被拔除。「打开向导 → 关闭 → 选章 → 连续键入」在代码级成立：键入路径上没有任何写 `selectedVolumeId` 的代码。
3. **显式关闭存在且有效**：`VolumeCloseWizard` 标题行新增「关闭」按钮，`onDismiss` → `setVolumeWizardId(null)`；关闭触发的 effect 重跑走 `outlineEnterRef.current` 早退，不改写选中态，作者留在原地继续编辑。全仓此前无任何 `setVolumeWizardId(null)`，现在有了。
4. **完卷自动打开同样可关**：三条自动打开入口（章结算 `queueMicrotask`、批量任务收尾、`DailyStatusBar` 跳转）与手动入口共用同一渲染点，同一个「关闭」按钮生效。
5. **不再画错卷**：向导仅在 `selectedVolumeId === volumeWizardId` 时渲染（顺带消除了上轮遗留 4 的「A 卷向导画进 B 卷卡片」）。
6. **回归覆盖**：`outline-focus.test.ts` 四条（刚打开 snap、保持打开不再 snap、关闭后不 snap、换卷再 snap）。

## 二、B2（润色确认后草稿陈旧）—— 已消除

1. **外部写入立即可见**：`OutlineChapterDetail` 用渲染期派生同步——`outlineChapterDraftSnapshot` 对比传入 `chapter` 与 `lastSynced`，同 id 外部写入（润色确认、「写这一章」写回摘要等）会立刻把 `draft` 换成 `mergeIncomingOutlineChapter` 的结果，面板即刻显示润色后文本。
2. **合并策略明确、按字段粒度**：外部改过的字段以外部值为准；作者本地未 flush 的编辑只在「该字段外部未动」时保留。`retainPendingAfterIncoming` 把已被外部改写的字段从 pending 拿掉，`useLayoutEffect` 同步进 `persistRef`，后续防抖 flush 不可能再用旧文本盖掉润色结果（layout effect 先于任何定时器宏任务执行，无空窗）。
3. **单测覆盖判据场景**：`outline-edit.test.ts` 新增「polish 确认 → 面板 summary 为润色后文本 → 键入一字 → 落库值为润色文本+一字」与「陈旧 pending 不得覆盖润色字段」。
4. **自写回声无副作用**：组件自身 flush 落库引起的 chapter 更新也走同一合并；此时 pending 已清空、incoming 与 draft 等值，面板无跳变。`update()`（`useProjectStore`）是同步 `setState`，React 18 批处理保证回声渲染在下一次键入事件前提交，不存在丢键窗口。

## 三、新洞排查——无 blocker，三条观察

1. **snap 记忆残留（窄路径，一次点击可恢复）**：若向导曾在大纲页内为 A 卷打开过（`prevWizardIdRef` 记为 A），作者未关闭就离开大纲页，之后从 `DailyStatusBar` 再次跳转同一 A 卷过卷——`shouldSnapToWizardVolume("A","A")` 为 false，落点会是推荐章而非 A 卷详情，向导暂不可见；点一下 A 卷节点即可见并可关。属上轮已拒的 P-3「待办向导横幅」范畴，不拦截。
2. **「关闭」不消费待过卷条件**：关闭只清 `volumeWizardId`，卷摘要仍为空时下一次完卷事件会再次自动打开。语义上是「每次完卷提醒一次、每次都可关」，符合预期，不拦截。
3. **给后人的提醒**：`OutlineChapterDetail` 的防丢键推理依赖 `onPatch` 同步落库（见二.4）。若日后把 `onPatch` 改成异步（例如先 await 再 setState），flush 与回声渲染之间会出现真实的丢键窗口，届时需在 flush 处同步更新 `lastSynced`。
