# 墨生万象（Inkborne）· 首页与侧栏收敛方案

> 状态：**规划文档，本 PR 只含本文件，不改业务/UI 源码，不 bump 版本，不改 appId / 安装包名。**
> 基线：`master` @ v2.1.0（P0–P2 已发：`#/author` 作者页、侧栏作者卡 + 「在创」封面墙、书架 Dashboard、书房四步、问心故事卡、研墨定稿）。
> 上位文档：`docs/墨生万象-UI与四步流程重构方案.md`（下称「四步方案」）。本文只修正其 B.1 / B.3 / E.1 / H.2 四处，其余（四步状态机、硬闸、视觉）不动；修正点集中列在附录。
> 用户反馈：试用 v2.1.0 后认为首页与侧栏仍乱，要求收敛。六条硬性需求全部纳入，编号 R1–R6。

## 〇、一段话结论

首页（`#/`）从「书籍列表」改为**作者书房首页**：顶部只读的头像 · 作者名 · 简介，其下是**带封面的书架**（全部作品，按在创 / 暂停 / 完结分组）。所有编辑控件（换头像、移除、字数限制、保存）离开首页，收进「**作者资料**」页（复用现 `#/author`，入口在系统设置与首页头像悬停铅笔）。侧栏删除「在创」封面墙与「日志记录」，其余按钮统一成**两列网格**；「守护进程」改名「**AI 动态**」并默认在线展示引擎事件流，但**自动连载调度器不默认启动**（它会立刻自动写章，见 E 章风险）。「对谈」一词退役，全线统一为「**问心**」：进程条第一步「问心」直接打开问心抽屉，故事卡钉在抽屉顶部，侧栏「对谈记录」改「**问心记录**」。顶栏左上「中 / EN」切换按钮移除，创作语言改为「项目设置」里的一项。

## A. 现状问题（对照当前源码）

编号：A1 首页/作者，A2 侧栏，A3 守护/日志，A4 问心/对谈，A5 语言切换。每条「证据 → 影响 → 处置」。

### A1 首页与作者页（`Dashboard.tsx` / `AuthorPage.tsx`）

- **A11 首页不是「作者的首页」。** `Dashboard.tsx` L303–535 渲染的是一行一书的列表卡（书名 · 题材 · 章数 · 状态 · 落墨按钮 · 统计 · 菜单），没有头像/作者名/简介，也没有封面。→ 用户进入软件先看到一堆操作按钮而不是「我和我的书」。→ 处置：B 章线框。
- **A12 封面只在侧栏出现。** `DefaultCover` 只被 `Sidebar.tsx` L433 使用；首页 `BookOpen` 图标代替封面。→ 首页与侧栏视觉断裂，用户要在 260px 侧栏里看封面。→ 处置：封面墙搬到首页，侧栏删除。
- **A13 首页每本书带主 CTA「落墨 · 写下一章」（L479–502）。** 与四步方案 A02「只保留书房今日一笔与落笔页两处」相悖（P1-4 后本应删除，遗留）。→ 处置：首页卡不带写作 CTA，只进书房。
- **A14 作者页把展示与编辑揉在一起。** `AuthorPage.tsx` L102–162：头像旁直接放「更换头像 / 移除」，输入框标签带 `≤24` / `≤300`，底部「保存」。侧栏作者卡点进来就是这张编辑表单。→ 用户想「看自己」，看到的是「填表」。→ 处置：首页只读；编辑收进「作者资料」。
- **A15 首页顶部「书架」大标题 + 副句「打开一本书进入连载书房」 + 右上「新建书籍」，再加未配模型横幅。** 四个视觉焦点。→ 处置：首页头部只剩作者头图文；「开始创作」只在侧栏。

### A2 侧栏（`Sidebar.tsx`）

- **A21 「在创」与首页书架重复。** L420–559 一整块封面墙（含每本书的 `⋯` 菜单：书房 / 导出 / 设置 / 移入书架 / 删除）。→ 同一本书两处入口、两套菜单。→ 处置：删除整块及其菜单、`deleteBookTarget` / `deleteShortTarget` / `pauseBook` 等仅服务于它的状态；「查看全部书架」也随之删除。
- **A22 三种按钮排版并存。** 「开始创作」是两列网格（`grid grid-cols-2`，`CreateItem`）；「工具」「系统设置」是单列 `SidebarItem`（L780–843）；「问心记录」是树形折叠列表。→ 视觉不齐，用户感知「乱」。→ 处置：C 章两列网格规则。
- **A23 侧栏顶部作者卡（L399–418）跳到编辑页 `#/author`。** → 处置：点击回首页 `#/`。
- **A24 「代理在线」绿条（L847–856）与「守护进程」项的 `running` 徽标重复表达同一状态。** → 处置：合并到「AI 动态」按钮的状态点。

### A3 守护进程与日志（`DaemonControl.tsx` / `LogViewer.tsx` / `server.ts` L5047–5102）

- **A31 「守护进程」在 InkOS 语义里是自动连载调度器。** `Scheduler.start()`（`packages/core/src/pipeline/scheduler.ts` L58–63）**立即** `triggerWriteCycle()`，随后每 `writeCron`（默认 15 分钟）对所有 `status ∈ {active, outlining}` 的书自动写 `chaptersPerCycle` 章（L177–200）。→ 用户以为它是「监控」，其实是「代写」。→ 处置：E 章拆成「AI 动态（默认开）」与「自动连载（默认关）」。
- **A32 「日志记录」页读 `inkos.log` 原文（level / tag / message 单色等宽）**，`LogViewer.tsx` 全是工程视角。→ 对作者无意义，且与 A05「工程语汇泄漏」相悖。→ 处置：删除入口，保留页面与 API 给排障（`#/logs` 深链仍可打开）。
- **A33 守护进程页事件流只在 `running` 时有内容**（`DaemonControl.tsx` L108–111 `startHint`），但引擎其实随时在广播 `write:* / weave:* / agent:* / tool:* / book:* / log` 等 SSE 事件（`server.ts` `broadcast(...)` 共 40+ 种）。→ 用户「看不到 AI 在做什么」并非缺监控，而是入口被绑在调度器开关上。→ 处置：AI 动态页无条件订阅现有 SSE，无需新监控系统。

### A4 问心 / 对谈双名（`BookWorkspaceNav.tsx` / `App.tsx` / `BookAskPage.tsx` / `Sidebar.tsx`）

- **A41 同一个抽屉两种叫法。** `App.tsx` L449–477 抽屉标题「对谈」；`BookWorkspaceNav.tsx` L167–178 按钮「对谈」；`BookAskPage.tsx` L100 副句「重开问心只开新对谈」——「重开问心」的动作是打开「对谈」抽屉。→ 用户读不出问心与对谈的区别（本来就没有）。
- **A42 进程条里「问心」步与「对谈」按钮并列**（`BookWorkspaceNav` L140–178）。点「问心」进 `#/book/:id/ask` 只读故事卡页；点「对谈」开抽屉。→ 想和 AI 聊要先判断该点哪个。
- **A43 侧栏「对谈记录」下又分「书名 → 会话」与「项目对谈」**（L591–770），会话操作叫「新建会话 / 重命名会话 / 删除会话」。→ 问心 / 对谈 / 会话三个词指同一件事。→ 处置：D 章对照表。
- **A44 短篇侧已经统一为「问心」**（`ShortReader.tsx` L40、`short-study.ts` L54「继续问心」）。→ 长篇向短篇对齐即可。

### A5 语言切换（`App.tsx` L234–254 / `LanguageSelector.tsx` / `ProjectSettings.tsx`）

- **A51 顶栏右侧常驻「中 / EN」分段按钮**（用户称「左上角中英文切换」，实际在顶栏右侧、主题切换左边），`PUT /project {language}` 即时切换。→ 高频位置放低频操作，且误触会整站换语言。
- **A52 首启 `LanguageSelector` 底部写「可在设置中更改」，但 `ProjectSettings.tsx` 里没有语言项**（grep `language` 为 0）。→ 承诺落空；删掉顶栏按钮后必须补上，否则语言不可改。→ 处置：F 章。

## D. 「问心」统一命名（R4 / R5）

### D.1 信息架构决定

「问心」= 与 AI 对话，是**动作**也是**第一步**。两者不冲突：第一步的产物（故事卡）是问心的沉淀，而不是另一个页面。因此：

1. **进程条第一步「问心」点击 → 切换问心抽屉**（`nav.onToggleChat`），不再跳 `#/book/:id/ask`。步骤状态点（done / current / todo）照常显示。
2. **「对谈」按钮（`book-tab-talk`）删除。** 进程条右侧只剩 `⋯`。

## E. 守护进程默认开 + 日志入口删除（R3）

### E.1 先纠正一个前提

用户要的是「看到 AI 在做什么」。现有「守护进程」不是监控，而是**自动连载调度器**：启动即对全部在创书自动写章、每 15 分钟一轮、每日上限 50 章（A31）。若把它「默认打开」：

- 用户一装好、配好模型，所有 `active/outlining` 的书就开始后台消耗 token 写章；
- 绕开书房「今日一笔」的作者节奏，与四步方案「一切落墨由作者点击」的硬闸精神相悖（G1 预检仍生效，但「写不写」不再由人决定）；
- 与书内手动落墨争抢书锁（`isWritingBook` / `BookBusyCard`「写入被占用」会频繁出现）。

因此拆成两件事：**「AI 动态」默认开**（满足需求），**「自动连载」显式开关、默认关**（规避风险）。若产品方仍坚持调度器默认启动，见 E.4 备选。

### E.2 「AI 动态」页（改造 `DaemonControl.tsx`，路由 `#/daemon` 不变）

```

│ AI 动态                                          ● 正在写《醉词》第 3 章 │  ← 顶部状态句（空闲：「引擎空闲」）
│                                                                     │
│ 最近动态（实时）                                                       │
│  14:02  《醉词》 落墨 · 第 3 章 起草中 … 1,240 字                       │  ← write:start / llm:progress

│ 自动连载                                              [ 关 ○——● 开 ]   │  ← 原 start/stop

│  上次自动写章：—                                                       │
└─────────────────────────────────────────────────────────────────────┘
```

- **默认态**：页面打开即订阅 `useSSE()` 已有的消息流（`App.tsx` L70 全局只有一个连接，`DaemonControl` 已接收 `sse` prop），把 `daemonEvents` 过滤条件从 `daemon:* | log` 扩成白名单：`write:* / weave:* / revise:* / rewrite:* / agent:* / tool:* / book:* / short:* / import:* / style:* / daemon:* / llm:progress / task:snapshot`。**不新增后端接口、不新增事件类型、不落盘**，只是把已经在广播的事件用中文句式渲染（映射表放 `lib/copy-map.ts` 旁的 `lib/activity-copy.ts`，纯函数，可测）。
- 顶部状态句由 `deriveActiveBookIds(sse.messages)`（`use-book-activity.ts`，已有）+ 最近一条 `write:start` / `weave:start` 推导。
- 侧栏「● AI 动态」的状态点与此同源：有活动书 → 松绿呼吸；否则灰点。**`/daemon` 的 `running` 不再驱动侧栏状态**（它只表示调度器）。
- 「自动连载」开关 = 现 `POST /daemon/start` / `stop`；文案按 `daemon.schedule.writeCron` / `chaptersPerCycle` / `maxChaptersPerDay` 生成。**默认关**，重启引擎不记忆开启状态（现状即如此，`schedulerInstance` 是内存变量）。
- 「日志记录」入口删除后，「AI 动态」页底部加一行灰字「排障：打开原始日志」→ `#/logs`（保留 `LogViewer.tsx`、`GET /api/v1/logs`、路由 `logs`），满足支持场景而不占侧栏。
