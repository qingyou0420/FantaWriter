# 《从零连载长篇流程》落地方案：界面与功能怎么改

> 尺子只有一份：`docs/从零连载长篇流程.md`（下称「流程文档」，阶段〇到九）。
> 对照对象是 1.5.1 的真实界面与数据流，逐个面板、逐个字段核过，不是凭旧方案文档臆造。
> 本文只做规划，不改代码。分工不变：骨架和灵魂由作者定，章节正文由 AI 写；写偏 / 写错 / 写歪靠账本和契约拦，不靠再叮嘱。

---

## 一、落地之后：每天打开软件会怎么走

打开项目，不再落在「人物设定」页，而是直接落在**正文页**，顶部一条今日状态：「未审 2 章 · 3 条伏笔悬置超期」。你先点未审的章，右侧并排着这章的契约和摘要，你按三遍读法过正文；读完点「定稿」，软件把四件套一件件递到你手上——摘要给你过目手改、本章人物状态变化列出来等你确认（不再是背着你静默入账）、本章触及的伏笔列出来让你标推进或回收——都点完，这章才变成「已审」。未审章清零后，扫一眼顶部的伏笔提醒，该给响动的记进大纲。

然后写今天的章。点「写下一章」，不再直接开跑，而是先弹出**本章契约**：本章目标和大纲摘要（还成立吗？过时就地改）、章末钩子、出场人物勾选、时间与地点、出场人物的账本现状（只读，供你核对）、**本章禁写清单**（全书禁写自动带入，本章特有的自己补一两条）、上章结尾自动带上。「要写什么」和「不能写什么」两栏都不空，「生成」按钮才亮。生成完，三遍读，皮肉错局部改，骨头错回契约补一条禁令重生成。定稿四件套，走人。离卷尾还有几章时，完卷横幅提前出现，把卷摘要、出卷人物快照、伏笔清点、时间线落点这四样冻结的活一步步领着你做完，新卷第一章的契约你只靠冻结物就能立起来。

而你的底牌——主题一句、结局方向、每个人物的真相层、「仅作者」的暗线内容——在软件里终于有了自己的家，界面上明确标着「仅作者 · 永不进提示词」，而且是真的永不进：注入逻辑对这些字段是白名单外，有测试锁死。AI 知道人物「现在什么样」，不知道「他为什么是这样、最终会变成什么样」。

---

## 二、一条贯穿所有改动的红线

**灵魂档案永不注入提示词。** 具体指四样：前提卡里的「主题一句」和「结局方向」、人物的「真相层」、「仅作者」伏笔（暗线）的内容。暗线要拦 AI，只能以作者亲手写的禁令形式（写进禁写清单，如「不得暗示 X 与 Y 的血缘」），不能以剧情内容的形式自动注入——哪怕附带「不得泄漏」的指令也不行，模型看见了就是看见了。

这条红线在 1.5.1 里有多处破口（见 P0-1、P0-5）。所有新增的「仅作者」字段，验收标准里都必须包含「注入组装逻辑不读取此字段，且有测试锁住」。

## 三、P0：没有这些，一轮流程走不完

### P0-1 前提卡：给阶段〇一个家

**对应流程环节**：阶段〇（一句话前提、主题一句、结局方向、第一版禁写清单）；阶段四（全书禁写自动入契约）。

**现状**：四样东西没有统一的家，而且现有的近亲字段全都注入提示词，正好反着：

- 「故事前提」是 `outline.premise`，藏在**大纲面板**里，通常是 AI 生成大纲时回填的——顺序颠倒了，流程要求前提先于一切。
- 「主题」是 `background.themes`（故事背景面板），每章生成都随 `formatBackground` 注入——流程明说主题「只给自己看，永远不进提示词」。
- 「结局方向」是 `outline.endingNote`（大纲面板「结局走向」），每章正文提示词里都带着「结局走向：…」——如果结局是反转，这就是每章都在给模型递写歪的火种。
- 第一版禁写清单：无处可放。最接近的 `settings.extraRules`（附加系统规则）语义是文风规则，不是剧情禁令。

**改法**：

- 界面：项目「设定」阶段新增第一个 tab **「前提卡」**（排在「人物设定」之前；新建从零项目后默认落在这里）。四个字段：一句话前提、主题一句、结局方向、全书禁写清单（一行一条）。主题和结局方向的输入框旁边直接标「仅作者 · 永不进提示词」。
- 数据：`NovelProject` 顶层新增前提卡结构（前提 / 主题 / 结局方向 / 全书禁写清单四个字段）。`outline.premise` 与前提卡的前提做单向兼容（老项目导入时带过来），大纲面板不再是前提的编辑处。
- 故事背景面板的「主题」字段（`background.themes`）保留原语义——它是给 AI 的题材倾向，继续注入；但在它旁边注明「此栏会注入。你只给自己看的主题一句，请写在前提卡」。两个「主题」各司其职，不合并。
- 注入：一句话前提**可**注入（它本来就是要给 AI 当锚的）；主题、结局方向**永不**注入正文与续排提示词——即同时把现在正文提示词里的「结局走向：`endingNote`」拿掉。作者若想在排大纲时给 AI 收束方向，在大纲/续排界面提供一个显式勾选「本次把结局方向给 AI 参考」，默认不勾。全书禁写清单自动带入每章契约（见 P0-3），以「禁止」清单形式注入。
- 首页「从零开写」创建项目后，「开写四步」引导卡改为五步，第一步是「填前提卡」。

**怎么算做完**：新建项目第一眼看到前提卡；四个字段落库；任何一章的组装产物里搜不到前提卡的主题一句与结局方向原文（测试锁住）；全书禁写清单出现在每章契约的禁写栏里。

### P0-2 人物真相层：有专属的家，且默认不进提示词

**对应流程环节**：阶段一（真相层五项）；阶段五「声音遍」；阶段八写偏治法。

**现状**：`Character` 没有真相层。字段只有外貌 / 性格 / 背景 / 关系 / 备注 / 别名 / 说话风格，且 `formatCharacters` 把**全部**字段注入出场人物提示词。作者要是把「他真正缺的是父亲的承认」写进备注，就等于每章都亮牌。

**改法**：

- 界面：人物编辑弹窗底部新增一个折叠区块**「真相层（仅作者 · 永不进提示词）」**，四个小字段：表面欲望、真实需要、致命缺陷、底线。默认折叠，视觉上与上面会注入的字段明显分隔（比如底色不同 + 锁形图标）。
- 声音样本不放真相层：流程阶段八明说「声音漂了，检查你的声音样本还在不在注入」——声音样本是要注入的，归入现有的 `speechStyle`（说话风格）即可，把该字段的提示文案改成「三句他会说的话，作为声音样本（会注入）」。
- 数据：`Character` 新增真相层子对象（四个字符串字段）。
- 注入：`formatCharacters` 及所有人物相关提示词组装（含 AI 扩写人设、一致性检查）一律不读取真相层。注意「AI 扩写此人设 / 优化草稿」也不能把真相层发出去——AI 往真相层外糊肉时，看到的是不含真相层的人物卡。
- 人物列表的完成度指标不把真相层计入必填（它是作者的私账，不逼填）。

**怎么算做完**：真相层四字段能存能改；全部生成路径（正文、大纲、续排、人物扩写、一致性检查）的组装产物里搜不到真相层内容，测试锁住；界面上「仅作者」标识肉眼可见。

### P0-3 本章契约：把「立契约」变成生成前的一个真实步骤

**对应流程环节**：阶段四全部七条；阶段九第 4、5 步（先核大纲再立契约）。

**现状**：契约的七条散落三处、缺两条、且没有「立契约」这个动作：

- 有家的：本章目标（大纲章的「剧情摘要」+「关键情节点」）、章末钩子（`hook`）、出场人物（`CastPicker` / `castIds`）、约束现状（人物状态账本自动进记忆包，但作者在生成前**看不到**它）、上章结尾（记忆包自动带末尾 1000 字）。
- 没家的：**本章禁写清单**（完全没有这个字段——流程说「写歪几乎都是这一条空着造成的」，现在它连空着的机会都没有）；时间与地点（只能挤在关键情节点里）。
- 没动作：点「生成本章 / 写下一章」直接开跑，没有任何生成前核对。代码里的 `BeatContract`（「本拍契约」）是原作焕新按拍扩写的自动产物，不是作者立的章级契约，别复用它的名字和路径。

**改法**：

- 界面：点「写下一章」或大纲页「生成本章」，先进入**「本章契约」**视图（正文页内的一个前置面板，不是新 tab）。从上到下：
  1. 本章目标：就地展示并可编辑大纲章的剧情摘要与关键情节点（对应阶段九第 4 步「大纲还成立吗？过时就先改」——改的就是这里，存回大纲章）；
  2. 章末钩子：现有 `hook` 字段搬进来；
  3. 出场人物：现有 `CastPicker` 搬进来；
  4. 时间与地点：新增章级小字段；
  5. 约束现状：**只读**展示出场人物的账本最新几条（数据已有，缺的只是生成前给作者看这一眼）；
  6. 禁写清单：新增章级字段，一行一条；顶部自动带入前提卡的全书禁写清单（只读），下方是本章增补（可写）。
  7. 上章结尾：自动折叠展示（已有能力，露出来）。
- 门槛：「本章目标」或「禁写清单」为空时，生成按钮旁给醒目提示（本章目标为空则禁用生成；禁写清单为空允许生成但要点一次「本章确无禁写」确认——契约两栏都不空才许按生成，但不把作者堵死）。
- 数据：章级新增「禁写清单」「时间与地点」两个字段（挂在大纲章上，与 `hook`、`castIds` 同级）。
- 注入：契约作为一个整块注入本章提示词——目标、钩子、出场、时间地点、约束现状、禁写（全书 + 本章，以「禁止写：」清单形式）。**注入的仍然只是契约 + 滚动记忆**，与阶段四「注入什么」的清单一致。
- 批量队列（本卷队列等）跑到某章时沿用该章已立的契约字段；没立过契约的章禁写栏为空，照常生成——批量路径不弹视图，但连载项目的主路径是「写下一章」（见 P1-1）。

**怎么算做完**：从「写下一章」到正文生成必经契约视图；禁写清单字段存在、注入形式为禁令清单；契约视图里能看到账本现状与上章结尾；在契约视图里改大纲摘要能存回大纲。

### P0-4 定稿四件套：把「标为已审」从一个开关变成一套动作

**对应流程环节**：阶段五「定稿四件套」；阶段六「账本错比没有账本更糟」；阶段九第 1、2、8 步。

**现状**：「标为已审」只翻 `reviewState` 一个开关。四件套里三件没有着落：

- 过摘要：摘要自动生成、可手改（能力在），但定稿动作不经过它——作者可以从没看过摘要就标已审。
- 过账本：**最糟的一处**——摘要附带的人物状态增量是**静默合并**直接入账（`mergeCharacterStates`），没有「提议 → 确认」。流程表格里写明账本是「AI 提议增量、你确认」；现在账本在没人过目的情况下滚动，账错了往后每章都被错账喂。
- 过伏笔：摘要只写入「本章触及」（`touchedThreads`），伏笔状态要作者自己想起来去「检视 → 伏笔」页手动改，和定稿动作完全脱节。

**改法**：

- 界面：正文页的「标为已审」改成**「定稿…」**，点开一个四步清单（同一个面板内走完，不跳页）：
  1. **过摘要**：展示本章摘要，可就地手改，「摘要没问题」勾一下；
  2. **过账本**：列出本章 AI 提议的人物状态增量（谁、什么变化），每条可改可删，点「入账」才合并进账本——静默合并改为暂存提议，定稿时确认；
  3. **过伏笔**：列出本章触及的伏笔（现有 `touchedThreads` 匹配），每条给三个快捷动作：推进中 / 已回收 / 不动；旁边一个「补记一条」入口（本章埋了新伏笔时用）；
  4. **标已审**：前三步走完（或对某步显式点「跳过」），按钮亮起。
- 数据：人物状态增量从「即刻合并」改为挂在章上的**待确认提议**；确认后才写入 `characterStates`。伏笔快捷动作复用现有的状态与回收章字段。
- 「未审 N 章」的现有提示保留并提级（见 P0-6）。

**怎么算做完**：不经过四步面板无法把章置为已审（跳过要显式点）；人物状态增量在确认前不出现在下一章的记忆包里；在定稿面板里能直接改伏笔状态；手改摘要立即生效于后续注入（现有能力，保持）。

### P0-5 堵住暗线与底牌的四处泄漏

**对应流程环节**：阶段二（「仅你知道」的暗线决定哪些东西永远不能进提示词）；阶段四「注入什么」；阶段六两条铁律之二。

**现状**：伏笔板的文案承诺「仅作者的暗线不会泄漏给模型正文」，但只对整章记忆包成立。核代码发现四处破口：

1. **按拍扩写的「本拍契约」**把所有未回收的「仅作者」暗线以「暗线（仅作者可见，正文不得提前泄漏）：- 标题：备注」的形式**连内容一起**注入——模型全看见了，只是被嘱咐别说。这正是流程点名反对的「靠再叮嘱」。
2. **「续排本卷 N 章」**把全部未回收线索注入，**不过滤可见性**——暗线标题和备注直接进大纲生成提示词。
3. 正文提示词默认注入**「结局走向」**（`endingNote`，见 P0-1）。
4. 正文提示词注入**全书大纲**（「## 全书大纲（供连贯性参考）」）——未来章的安排也是底牌的一部分，且稀释注意力（收窄之事放 P1-7，此处先把暗线相关的前三处堵死）。

**改法**：

- 按拍扩写：契约块里删掉暗线段。要拦模型，靠 P0-3 的禁写清单（作者手写禁令）。
- 续排本卷：线索注入处套用与记忆包相同的「读者已知」过滤。
- 结局走向：随 P0-1 从正文提示词移除。
- 伏笔板文案改为与事实一致：「仅作者的暗线不进任何提示词；要拦 AI，请把禁令写进本章契约的禁写清单。」

**怎么算做完**：全部生成任务（正文、按拍、续排、大纲、一致性）的组装产物里搜不到「仅作者」线索的标题与备注，测试逐路径锁住。

### P0-6 每日动线：打开先审，审完再写

**对应流程环节**：阶段九第 1—3 步（先审后写、四件套、扫伏笔账）；两条不缩的底线之一。

**现状**：打开项目默认落在「人物设定」tab（连载中的老项目也是）；「未审 N 章」提示存在但埋在正文页侧栏；伏笔悬置提醒在「检视 → 伏笔」，每日第 3 步要跨两级导航才能看到。整个三段导航「设定 → 创作 → 检视」是建书顺序，不是每日顺序——审与账被排在最后一段，作者每天却要先用它们。

**改法**（纯信息架构，不新造能力）：

- 默认落点：已有大纲的项目，打开默认进**正文页**；从零新项目默认进**前提卡**。
- 正文页顶部一条**今日状态栏**：「未审 N 章（点击跳到最早未审章）· M 条伏笔悬置超期（点击展开清单）」。数据全部现成（`reviewState`、`isPlotThreadOverdue`），只是把它们提到每天第一眼。
- 软性拦截：存在未审章时点「写下一章」，先提示「还有 N 章未审，先审再写？」，可以「仍要写」——提醒不堵死，但默认路径是先审。
- 章列表排序：未审章置顶标黄（黄点已有，提级为排序依据）。

**怎么算做完**：连载中项目打开即见未审章与伏笔提醒；从「打开软件」到「审完第一章」不需要切换 tab。

## 四、P1：没有这些，能走完但别扭

### P1-1 连载项目的默认值与主按钮

**对应流程环节**：总则「一键出全书不是正路」；阶段四钩子条款；阶段九整体。

**现状**：`serialMode` 默认关——章末钩子写了也不进正文要求，结尾照样写圆；顶栏主 CTA 是「一键生成正文」和「更多 → 强制全量重写」，与流程主张的一章一契约相反；「写下一章」反而藏在正文页里。

**改法**：从零新建项目时，前提卡页给一个「连载长篇」开关，**默认开**（即 `serialMode` 默认 true；老项目不动）。连载项目的顶栏主按钮改为**「写下一章」**（走 P0-3 契约视图），「一键生成正文 / 强制全量重写」收进「更多」并在连载项目下加确认文案「连载的正路是一章一契约，确定批量生成？」。批量队列本身保留（补稿、重试失败仍需要它）。

**怎么算做完**：新建连载项目不动任何设置，生成的正文就带钩子条款；顶栏第一眼是「写下一章」。

### P1-2 账本的「写死条目」：长期约束不许被挤掉

**对应流程环节**：阶段八写偏治法（「把话补进账」：他此后对师父只称您）；阶段六账本铁律。

**现状**：人物状态账本每人只保留**最近 6 条**，先进先出。作者按流程把「左臂未愈不能持重剑」写死进账，六章之后这条就被日常增量挤掉了——治写偏的主力药自己会过期。

**改法**：账本条目支持**置顶（写死）**：人物页账本区每条旁一个图钉，置顶条不参与「保留最近 6 条」的淘汰、永远注入该人物的状态卡；普通条目照旧滚动。数据上给账本条目加一个置顶标记即可。定稿四件套的「过账本」步骤里也能直接把某条提议置顶。

**怎么算做完**：置顶条在 20 章后仍出现在注入的角色状态卡里；淘汰逻辑只作用于未置顶条。

### P1-3 过卷向导：冻结四样、开卷重定四样

**对应流程环节**：阶段七全部；阶段九第 9 步。

**现状**：过卷只有半件事——完卷时横幅催「生成卷摘要」。冻结四样里缺三样：出卷人物快照（`exitState` 是一句手填文本，无逐人快照）、伏笔清点（无「开放伏笔不许无去向出卷」的核对）、时间线落点（时间线 lore 是自动抽的流水，没有卷末落点动作）。开卷重定四样完全靠作者自觉。

**改法**：

- 完卷横幅升级为**过卷向导**（分卷页内走四步）：① 卷摘要（现有能力，AI 草稿你改定）；② 出卷人物快照——按主要人物列出账本现状让作者改定成快照，存卷上（新增卷级快照字段），并作为下一卷记忆包里「前卷终局」的来源；③ 伏笔清点——列出本卷开放线索，逐条要求给去向（本卷收 / 去第 X 卷，落到线索的去向字段，见 P1-4），有一条没去向就标红；④ 时间线落点——一行「故事此刻是何年何月」，存卷上。
- 开卷侧：新卷第一次「续排本卷」前，检查新卷的弧线目标 / 出卷局面为空则先弹出让作者填（重定四样的前两样有家了；暗线推进与禁写增补分别落在伏笔去向和前提卡禁写清单里）。
- 提前量：本卷未写章 ≤ 3 时，分卷页与正文页顶部出现「快到卷尾了：还有 N 条伏笔未定去向」的提示（对应阶段九第 9 步）。

**怎么算做完**：走完向导后，新卷第一章的契约只靠卷摘要、人物快照、伏笔去向、时间落点四样就能立起来，不用翻旧正文。

### P1-4 伏笔总账补「去向」维度

**对应流程环节**：阶段二总账（埋在哪卷、收在哪卷）；阶段七伏笔清点。

**现状**：`PlotThread` 只有「打算第几章前回收」（`dueChapterOrder`）和埋 / 收章 id，没有卷级去向。三十章悬置提醒有，但「这条最后收在哪」答不上来时软件帮不上。

**改法**：线索加「预计回收位置」（卷级即可，如「第 X 卷」+ 一句去向备注）。伏笔面板列表按「逾期 → 无去向 → 其它」排序；无去向的开放线索常驻一个浅色警示。过卷向导第③步读写的就是这个字段。**不注入提示词**（去向是作者的排程，不是给模型的线索）。

**怎么算做完**：每条开放线索都能在面板上看到去向或「未定」；过卷向导能按它清点。

### P1-5 审阅同屏：让三遍读不用来回跳

**对应流程环节**：阶段五三遍读（读者遍 / 事实遍 / 声音遍）。

**现状**：审一章时，正文在正文页，契约字段散在「大纲/场景」折叠区，账本在人物页，伏笔在检视段，声音样本在人物弹窗里——「事实遍」和「声音遍」各要跨两三个界面。

**改法**：正文页加**审阅侧栏**（未审章自动展开）：上半是本章契约（P0-3 立过的原样回显，事实遍逐条勾对的就是它），中间是出场人物账本现状与说话风格样本（声音遍对照用），下半是本章摘要。全部是现有或 P0 新增数据的**换位置展示**，零新字段。

**怎么算做完**：审一章全程不切 tab；契约、账本、声音样本、摘要与正文同屏。

### P1-6 写歪之后：给改线裁决搭扶手

**对应流程环节**：阶段八（定位 → 分诊 → 回填 → 复盘）。

**现状**：摘要快读回溯没有专门视图（要一章章点开看摘要）；「从漂移起点重生成」只能整章覆盖重生，改摘要之后没有任何「污染源已改，下游注意」的痕迹；将错就错的改线全靠作者在多个面板间手工同步。

**改法**：

- **摘要流视图**：正文页章列表加一个「只看摘要」模式，一屏纵览几十章摘要（对应「十分钟扫五十章」），点任意章摘要可就地改（改的就是账，现有能力换展示）。
- **修账痕迹**：手改某章摘要或账本置顶条后，该章之后的已生成章在列表上出现一个小标记「上游账已修」，提示作者按阶段八第三步做一到两章回填小修。只标记，不自动重生。
- 分诊本身不做成功能：改线是作者的活，软件把账本入口聚到一处就够。

**怎么算做完**：五十章的摘要能在一个视图里连读；修账后能看出哪些章在修账点下游。

### P1-7 注入收窄：全书大纲不再整本进提示词

**对应流程环节**：阶段六「写下一章时注入什么」（就这些）；阶段三铁律（大纲服从已写正文）。

**现状**：正文提示词带「全书大纲（供连贯性参考）」——所有章的标题摘要全量注入。与滚动记忆的设计重复，稀释注意力，且把未来章安排（部分是底牌）交给模型。

**改法**：默认只注入**本卷**的章级大纲（或当前章前后各几章）；更早的卷由卷摘要代表（记忆包已做）。设置里保留「注入全书大纲」开关给想要旧行为的人，默认关。

**怎么算做完**：默认配置下，组装产物里只含本卷的章级大纲；跨卷连贯靠卷摘要。

## 五、P2：锦上添花

- **前提卡自述验收**（阶段〇怎么验收）：前提卡页角落一个「三分钟自述」按钮，倒计时三分钟 + 一行提示「把这个故事讲给自己听，讲不顺就是没定死」。纯 UI，不调 AI。
- **磨刀石模式**（阶段〇 AI 做什么）：前提卡页的 AI 辅助不是「帮你写前提」，而是「追问」——把前提发给模型，只许它提问和列同类作品常见写法，不许它给成品。注入的仅前提本身。
- **一致性报告落账**（阶段六定期体检「报告是线索不是判决」）：报告的每条问题旁加「已核实 → 去修账」快捷跳转（跳到对应章摘要或人物账本），和「误报，忽略」标记。不自动改任何账。
- **十章体检提醒**（阶段九第 10 步）：距上次一致性检查新增已审章 ≥ 10 时，今日状态栏多一句「该体检了」。现有「队列完成后自动跑本卷」偏好保留。
- **声音遍辅助**：审阅侧栏的声音样本区加一个「抽本章对话」按钮，把本章某人物的台词抽出来和样本并排放。本地文本处理，不调 AI。
- **冲突一页**（阶段二）：前提卡下方给「核心对抗」一小块（谁对谁、争什么、为什么不能和解）。仅作者，不注入，过卷向导开卷步骤里回显它。

## 六、动哪些面、哪些字段、哪些默认（汇总）

**动的面板**：新增「前提卡」tab；人物编辑弹窗（真相层折叠区）；正文页（契约前置视图、定稿四步面板、今日状态栏、审阅侧栏、摘要流视图）；分卷页（过卷向导）；伏笔面板（去向字段与排序、文案更正）；顶栏（主 CTA 换成「写下一章」）；首页「开写四步」引导卡（加前提卡一步）。

**新增字段**（全部在项目 JSON 内，不动存储架构）：项目级前提卡（前提 / 主题* / 结局方向* / 全书禁写清单）；人物真相层*（表面欲望 / 真实需要 / 致命缺陷 / 底线）；章级禁写清单、时间与地点、待确认的账本提议；账本条目置顶标记；卷级出卷人物快照、时间线落点；线索去向（卷 + 备注*）。带 * 的字段仅作者可见，注入组装一律不读，并用测试锁死。

**改的注入行为**：移除正文提示词里的「结局走向」与（默认的）全书大纲全量注入；按拍契约与续排本卷不再注入「仅作者」线索；账本提议确认后才生效；契约块（含禁写清单）成为正文注入的一部分。

**改的默认**：打开项目默认落正文页（新项目落前提卡）；从零新项目连载模式默认开；未审章置顶；主按钮「写下一章」。

**实施顺序建议**：P0-5（堵泄漏，纯防御，先行）→ P0-1 / P0-2（新字段与红线测试）→ P0-3 / P0-4（契约与定稿，流程主干）→ P0-6（动线）→ P1 按编号。P0 之间除 P0-3 依赖 P0-1 的全书禁写清单外互不阻塞。
